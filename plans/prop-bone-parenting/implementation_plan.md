# 完整 PMX 道具的多骨骼外亲方案

日期：2026-11-07

状态：本轮已实现版本 2 同帧多骨骼外亲、自动注册补偿、JNI/舞台接入和编辑器操作。跨人物外亲、人物碰撞体代理和原作者折扇动作视觉验收不包含在本轮完成范围。

## 目标

保留完整道具 PMX 的网格、骨架、材质、Morph、刚体与关节。扩展现有时间轴，使同一帧可以分别登记多根道具骨骼到人物骨骼的外亲关系，保存注册时的相对补偿，并继续播放道具 VMD。

用户只需选择帧号、扇子骨骼、目标人物和目标骨骼。坐标转换、相对补偿、父子求值与播放恢复由程序处理。

## 当前证据

下列条目为实施前的调查基线；当前实现与验证见文末记录。

- 文档 `1.关于折扇运动的使用步骤（必看）.docx` 要求同帧依次登记不同道具骨骼，截图包含自动计算的相对位置和角度。3098 帧为全亲和中心分别绑定右手；3099 帧为全亲绑定右手、中心绑定左手；3168 帧还登记中心辅助 1 到右食指骨。
- “二次”不表示只保留两条全局关系。此前其他道具骨骼的绑定需要持续存在，直到该骨骼自己的后续登记或解绑。
- 文档在不同帧重复登记相同目标，不能以“父骨骼没变”去重；新的注册补偿可能不同。
- `PropTimeline` 只有一条模型级 attachment 状态。`PropTimelineEditor` 以帧号作为外亲键的唯一索引。`PropTimelineFiles` 明确拒绝 childBone，因此当前结构不能表达文档要求。
- Rust `BoneSet` 在物理前计算骨骼并向子节点传播；`MmdModel::tick_animation_internal` 再运行 Bullet 和物理后骨骼求值。现有普通外部骨骼 override 会直接替换动画输入，不能直接拿来承载要求保留 VMD 的外亲参考系。
- `prop_physics.rs` 已处理道具模型参考系变化、世界向下重力及动态刚体世界姿态保留。
- `doc/VPD_POSES.md` 和当前物理初始化、JNI 挂载链路共同表明：人物与独立道具仍使用各自物理世界。当前没有发现人物碰撞体同步到道具世界的链路，不能将两者碰撞视为已验证能力。

本地对照资产为游戏实例中的“梨花雪团扇 Ver1.00”，不是文档折扇。只读解析得到 2731 个顶点、6 根骨骼、6 个刚体、5 个关节；中心是根骨骼，下面是 F1、C1～C4 动态链。它缺少文档的全亲、中心辅助 1 和扇子要，不能用来宣称文档动作验收成功。审计记录位于 `build/fan-document-reference/local-round-fan-audit.json`。

## 数据和时间轴

采用版本 2，同时保留版本 1 的整模型挂载兼容路径。

每条绑定包含：

- 道具对象 ID、道具骨骼名。
- 目标人物对象 ID、目标骨骼名；默认目标为道具所属人物。
- 注册帧、同帧操作顺序、稳定关键帧 ID。
- 绑定或解除绑定操作。
- 注册模式及计算完成的相对位移、旋转；另存用户可调的附加握持变换。

编辑唯一性为“道具对象 + 道具骨骼 + 帧”。同帧允许不同道具骨骼分别登记；更新同一根骨骼同一帧的关键帧时替换原记录。

每根道具骨骼拥有自己的阶梯状态轨道。帧求值生成完整的有效绑定集合，而非一个全局 attachment。显隐继续作为独立轨道，既不删除绑定，也不销毁物理。

原生句柄不写入 JSON。目标对象在播放时解析为当前实例；跨人物引用预留稳定的舞台角色槽位，不依赖模型显示名称唯一性。首个运行阶段默认支持所属人物，在对象解析器完善后扩展到其他表演者。

## 注册和相对补偿

默认采用“注册时保持当前姿态”，另保留显式对齐新挂点模式。

注册按以下顺序执行：

1. 在隔离预览实例中求值注册帧，应用此前已生效的绑定。
2. 同帧有多次注册时，按文档或用户登记顺序处理，每次登记后更新受影响的骨骼子树。
3. 取得目标人物骨骼与道具骨骼的当前变换，转换到明确的模型/世界空间，求出保持当帧姿态的补偿。
4. 将补偿与参考姿态记录在关键帧中。后续播放使用该记录，不用当前预览帧重新生成它。

每帧从 VMD 输入和已保存的外亲状态重新求值，避免把外亲结果当成下一帧动画输入而累计。

外亲是独立的变换求值层，不重写 PMX 文件，也不把普通骨骼 override 作为替代。需要明确原父级贡献、外亲变换和被绑定骨骼自身 VMD 输入的组合规则，依据开源 MMD 实现核对，并以父子两级同时绑定的数值测试验证，不能仅凭矩阵直觉宣称完全兼容 MMD。

编辑已存在的注册关键帧时，从不含该旧关键帧的前置状态重新计算，保证相同输入重复保存不会改变结果。更改早期关键帧、参考动作、骨骼映射或模型缩放后，标记依赖它的后续补偿为需要重算；由明确的重新计算操作完成，不在绘制时悄悄重算。

直接跳到某帧、倒退、循环和中途加载都读取相同的绑定集合与补偿。运动学状态应与从头到该帧的播放一致。动态物理的精确历史重现另需预热或缓存，不与运动学一致性混为一谈。

## 原生骨骼求值

建议在 Rust 增加专用道具外亲输入，按帧批量提交；不要复用会覆盖 VMD 的 setBoneOverride 接口。

执行顺序：

1. 求值人物当帧最终姿态，取得目标骨骼变换。
2. 求值扇子 VMD、Morph 和原骨骼局部变换。
3. 在骨骼求值阶段应用外亲和注册补偿，并正确传播后代。
4. 用外亲后的骨骼同步跟骨刚体和关节锚点。
5. 推进扇子物理，回写动态骨骼，完成物理后骨骼与蒙皮。

CPU/GPU 路径共用这一原生输入和求值过程。版本 2 使用明确的道具模型参考系，避免在骨骼外亲之外再次应用旧版整模型挂手变换，造成重复变换。

未被直接外亲控制的动态穗子继续由 Bullet 回写。选择动态刚体直接控制的骨骼时，界面需明确提示控制权冲突；首轮不通过关闭物理强行实现贴合，优先选择其上级动画控制骨骼。

多人物绑定需要按依赖关系更新人物和道具，并检查跨模型环路；不能依靠角色绘制顺序碰巧正确。

## 碰撞

保留现有道具内刚体和关节。人物与道具的跨模型碰撞单独实施和验证。

适合首轮的方案是在道具物理世界建立人物碰撞体的运动学代理：

- 读取人物当帧求值后的碰撞体姿态，将其变换到道具物理坐标。
- 保留适用的形状、尺寸和碰撞过滤，建立清晰的代理过滤组。
- 代理只接收人物姿态，不反向驱动人物骨骼；先实现动态扇穗等与人物的单向接触响应。
- 检查缩放、模型切换、传送与释放时的代理生命周期。
- 同时覆盖默认 upstream1201 后端；legacy-physics 属于单独兼容验证范围。

强动画驱动的扇体不会因为增加碰撞代理就自动停止穿过身体。若需要整把扇子被身体推开，需要额外的握持约束/物理混合设计，不能用单向代理声称完成双向刚体互动。

## 图形编辑器

保留现有标尺、拖动定位、播放和显隐轨道。在外亲区域新增：

- 扇子骨骼选择，与人物骨骼选择分开。
- 每根已有绑定骨骼的子轨道；同帧标记可以同时显示和分别选中。
- “保持当前姿态注册”“对齐挂点”“解除绑定”。
- 当前帧有效绑定列表，显示目标人物、目标骨骼、注册来源帧和补偿状态。
- 骨骼缺失、动态骨控制冲突、跨模型环路和补偿失效的具体提示。

骨骼名称从真实 PMX 获取，不把某个作者的骨骼名称硬编码为通用语义。可依据本文档制作操作预设，但缺失控制骨骼时必须指出缺项，不以任意近似骨骼自动替代。

## 实施顺序与验收

1. 版本 2 数据、每骨骼轨道、序列化和旧文件兼容。验证同帧多个骨骼、不同时刻同目标重注册、独立显隐、解绑与保存回读。
2. Rust 外亲输入、骨骼参考空间和注册补偿。使用合成的全亲/中心/辅助骨、完整网格及 VMD 验证注册不跳变、旋转中心、父子传播和无累积漂移。
3. JNI、舞台与编辑器接入。验证从头播放、直接跳转、回退、延迟加载和反复编辑保存的运动学一致性；验证 CPU/GPU 相同骨骼结果。
4. 保留道具物理，补充人物碰撞体代理。用接触数量、动态刚体位移响应、关节锚点误差和资源计数验收，不只检查编译或画面接近。
5. 使用文档对应折扇 PMX、人物/扇子 VMD，核验 0、3098、3099、3167、3168、3370、3375 帧以及相邻帧的连续播放。当前本地团扇仅作对照，不能替代此项。

本轮不拆分资产、不重写 PMX、不修改现有刚体/关节参数，也不将合成测试当作原作者动作的完整复现。

- `PropTimeline`、`PropTimelineFiles`、`PropTimelineEditor` 增加每根道具骨骼的独立轨道、同帧稳定注册顺序、解绑及 v1/v2 回读保存。

- 现有完整道具 PMX、刚体、关节、Morph、VMD 和挂载物理参考系均保留；未修改用户资产，未向游戏实例安装构建。

本轮 JSON 使用单道具对象、目标固定为 `actor`。同帧顺序由数组稳定顺序承载，编辑唯一性为骨骼名与帧；没有提前引入跨人物槽位、稳定关键帧 ID 或碰撞代理。
