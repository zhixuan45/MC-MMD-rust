# 动作切换后的绑定隔离与补偿作用范围

用户已授权继续修复状态残留和补偿复用，保留旧版简单绑定。

## 已定位路径

- 舞台和普通挂载共用 `held-item/<player>` 道具缓存身份，舞台 VMD、外亲、物理参考系都写在同一原生模型上。
- `tryCustomAnim` 接替舞台时未清除 `playStageAnim`，未恢复第 0 层速度；舞台同步仍可定位新动作并保留道具会话。
- 时间轴补偿只有预览参考标签，运行时不校验人物模型、参考动作、道具资产和挂载配置。

## 实施

1. 舞台道具采用会话专属模型请求键；关闭会话时取消未完成加载并释放专属缓存。普通挂载保留原键和算法。
2. 普通动作接替舞台时交还第 0 层时钟，清除舞台标志，停止所属道具会话；帧同步检查当前角色是否仍受舞台控制。
3. 编辑器保存骨骼补偿时记录人物 PMX、道具 PMX/VMD、参考 VMD 的 SHA-256，以及参与坐标转换的配置。无参考动作表示明确从静止姿态注册，可用于其他动作；有参考动作时要求当前实际人物动作文件一致。
4. 运行时对不匹配或未登记来源的骨骼补偿给出一次具体原因，使用会话隔离的简单挂载，不加载该时间轴的道具动作。v1 旧时间轴和无时间轴路径保持兼容。
5. 编辑器发现来源变化时标记补偿需重算，保存先重算再登记来源。仅在打开/绑定/保存时计算文件校验，不在每次绘制中读取资产。

## 验证

先用用例复现旧缓存重用、普通动作时钟未交还及跨模型/动作补偿误用；修复后验证同一舞台内有效补偿、停止/替换/失败后的普通绑定、待加载会话释放、不同玩家独立、v1 兼容。运行 Java 回归、真实 JNI/界面探针及两平台构建。真实游戏中同动作切换后的表现仍单独验收。
