## 当前证据与未知项

上游 `rust_engine/src/physics/mmd_rigid_body.rs` 已有 `Static → FollowBone`、`Dynamic → Physics`、`DynamicWithBonePosition → PhysicsWithBone` 的映射。因此本计划针对运行行为，不把“不兼容”预先解释成缺少枚举分支。

已在固定上游检出中确认：原始 PMX 模式只在统一映射入口转换，之后由运行时模式控制跟骨、演算与回写。已将该入口的类型 2 映射为 `Physics`。实际 Bullet 对照中，原先类型 2 保留动画位置；改动后与类型 1 的完整矩阵回写一致。该结果证明用户要求的实验生效，不代表已经证明游戏原症状的根因。

本地 Git 使用 Schannel 访问上游时返回 `SEC_E_NO_CREDENTIALS`；已通过单次命令的 `http.sslBackend=openssl` 成功获取固定提交，未修改全局 Git 配置。

## 实施顺序

1. 获取并核对上游提交，检查该检出中的 `AGENTS.md`、索引、构建说明和加载器支持。构建未经修改的上游，记录代码 SHA、JAR/native SHA、配置与启动日志。若只能使用不同加载器，记录差异，不能把当前分支与上游的全部差异归因于物理。
2. 确认统一运行时模式入口及所有直接读取 PMX 模式的位置，保证类型 2 在构建、初始化、步进和回写时均采用类型 1 的路径。
3. 在统一模式映射处将 `DynamicWithBonePosition` 映射为 `Physics`，不更改解析器中的原始类型值，也不更改模型资产。
4. 验证类型 0 仍跟随骨骼，类型 1 保持完整物理，类型 2 与类型 1 使用相同模拟和完整变换回写。必要时用带非零初始偏移的确定性物理场景验证。
5. 构建并保存未经修改的上游与实验产物，再以固定场景比较。效果结论来自实际演算和游戏画面，不以枚举映射或编译结果代替。
