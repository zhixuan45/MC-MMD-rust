# Ray-MMD 材质与 FX 兼容修改计划

## 目标与范围

以现有 FX 效果包实现为基础，先让 Ray-MMD 原版常用材质能够准确导入并在现有 OpenGL 渲染路径显示，再按真实素材扩展兼容能力。现有角色、场景、逐材质选择和不支持项诊断继续保留。修改前重新检查工作区状态；保留用户和其他工作的改动。

完整 MME 运行时、任意 HLSL 执行及 Ray 全场景效果属于后续独立架构项目，不作为本计划前几阶段的完成条件。现有架构和 Tex_1 基线参见同目录 implementation_plan.md。

## 阶段一：原版默认材质与基础语义

1. 固定 Ray-MMD 上游提交，选取原版 material_2.0.fx 及其依赖作为测试输入，记录来源和哈希；先核对本项目 COMMON_HASH 与该版本的匹配情况。确认扫描、加载、材质覆盖、CPU/GPU 绘制和错误展示调用链。
2. 追踪 PMX SpecularPower 经 Rust/JNI 到 Java 材质及普通、批量 GLSL 的数据路径。Ray 文档指出默认光滑度由 PMX 镜面指数转换；上游 GetSmoothness 的来源 9 调用 ShininessToSmoothness(MaterialPower)。核对原版函数公式、边界、morph 和色彩空间后实现该来源，不能直接将 9 当作常量或纹理。
3. 核对原版默认材质的其他宏、默认值和公共源码哈希；逐项支持属于本阶段的选项，暂不支持的选项继续明确报错。不得为通过导入而跳过未知语义。
4. 为默认材质、不同 SpecularPower、常量及现有贴图来源补充针对性测试；核对普通绘制与批量数据布局一致。确认原版默认文件实际导入通过，已有 Tex_1 案例不回退。

涉及 RayMaterialImporter、FxEffect/FxMaterialData、材质数据传递及 fx_material.glsl；具体修改以调用链为准。参考：[Ray 材质说明](https://github.com/ray-cast/ray-mmd/blob/master/Materials/README.md)、[原版公共材质实现](https://github.com/ray-cast/ray-mmd/blob/master/Materials/material_common_2.0.fxsub)。

## 阶段二：常用材质选项

1. 根据实际 Ray 材质包统计未支持项，优先实现外置 alpha 及其 UV/通道、次法线、次基础色。逐项核对 Ray 原版混合、采样、默认值及纹理缺失行为。
2. alpha 必须贯通普通主体、透明分类与合成、深度封口和阴影路径；维护 PMX 材质 morph、CPU/GPU 与批量行为的一致性。不能只改变颜色 pass 的 alpha。
3. 视差、发光 morph、custom 材质模型等按样本和收益单独排期；未实现时给出具体原因。纹理路径限制、重载释放及失败回退继续遵守现有设计。
4. 分别验证常量、模型纹理、外部纹理、UV 翻转和重复、材质覆盖及缺失资源；使用针对性像素读取验证组合效果。

## 阶段三：光照近似与光影互操作

1. 选择固定模型与材质，在 MMD/Ray 建立参考图，记录贴图、光源、天空、曝光和色调设置；Minecraft 中记录同模型、姿态、相机、光照及光影配置。
2. 测量当前宿主材质实现与参考的主要差异，优先核对 BRDF、法线、颜色空间和曝光，制定可独立开关的改进；不要把光影包提供的效果标记为 Ray 已实现。
3. 测试无光影及目标 Iris 光影包，覆盖不透明、半透明、描边、阴影、CPU/GPU；不得破坏已有世界透明与水面合成。复杂场景光照或 IBL 若需要新增渲染资源和调度，先形成独立设计。

## 阶段四：复杂 MME FX 可行性设计

整理典型 FX 所需的 include/宏、语义绑定、顶点及像素阶段、控制器、渲染目标、多 pass、深度及外部绘制。选择少量真实效果制作能力矩阵，比较专用适配器与可控的渲染图方案，明确性能和 Minecraft/Iris 集成成本。先提交设计与验收样本，再决定实现；现有单 pass 颜色适配器继续对超出范围的效果报告不支持。

## 验证与交付

- 分层记录：解析与参数测试、GL 编译及像素探针、Java/平台构建、实际游戏效果，各自独立报告。
- 使用仓库现有 effectpack 测试和 tools/effectpack-probe，按变更补充有判别力的案例；避免仅验证镜像实现。
- 游戏中固定模型、动作、镜头与照明，至少比较效果关闭/开启、CPU/GPU 和无光影/目标光影；记录 FPS 或帧时间及透明、阴影回归。
- Ray 参考图与游戏图应记录各自色调和环境差异。构建或探针通过不替代游戏视觉验收；未执行的场景单独列出。
- 实施各阶段前确认实际素材和依赖可用；不分发第三方素材，引用上游代码或资源前核对对应许可。
