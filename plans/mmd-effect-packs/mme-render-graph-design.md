# 复杂 MME FX 的宿主适配设计草案

## 目标与范围

以真实效果为输入建立受约束的渲染图，供未来的专用适配器调用。现有 Ray 材质协议与单 pass 颜色适配器继续独立工作；此设计不声称支持任意 FX、HLSL 或完整 Ray 场景管线。具体实现应先选定真实素材及参考画面，再按能力逐项开放。

## 管线与资源

- 导入器生成版本化中间描述，记录资源依赖、shader 阶段、参数语义、pass 的输入输出、渲染状态及宿主调度位置。未知语义和未支持状态必须报告并拒绝该效果，不能静默丢弃。
- 图编译阶段验证依赖顺序、资源格式、尺寸、生命周期、读写冲突和设备限制；历史帧资源显式声明，不能把当前帧循环当作合法依赖。
- 宿主提供相机矩阵、视口、时间、场景颜色/深度等显式能力；缺失或与当前光影包冲突时给出诊断并停用该效果。模型材质与世界效果的输入和调度位置分别定义。
- 每个 pass 保存并恢复触及的 framebuffer、viewport、纹理、混合、深度、剔除和程序状态；临时纹理按描述复用，分辨率改变或效果重载时释放，避免逐帧编译和分配。
- Shader 转换必须保持阶段接口和数学语义；仅接受已验证的语言子集，编译失败和不支持的内建函数应定位到原文件。include 及资源路径继续限定在效果包内，保留大小和数量限制。
- MME 控制器对象映射为明确声明的宿主参数或动画通道，不能假设 Minecraft 存在 MMD 控制器；缺失控制器时使用文档化默认值或拒绝。

## 调度与兼容

模型材质效果在现有材质提交中执行；深度、透明和阴影分别使用与实际宿主兼容的阶段。世界效果只能挂接在明确拥有颜色与深度的生命周期点，并明确和 Iris 后处理、HUD、世界透明合成之间的顺序。不得覆盖光影包的 G-buffer 或假设其 attachment 布局。

外置 alpha 是独立子问题：应由统一材质 alpha 表达式驱动颜色、透明分类、深度和阴影；宿主阴影 shader 不提供该表达式的接入点时，需要适配对应 shader 或明确报告不支持。透明候选与 GPU 剔除不得使用只适用于 PMX 原始纹理的覆盖率裁剪。

## 分步实现与验收

1. 选取一个真实双 pass 颜色效果，固定其版本、依赖及参考输出，先支持单个全屏目标和显式采样；实现资源图、状态恢复及故障诊断。
2. 扩展到深度输入或中间目标前，先确认目标渲染阶段和光影包的实际资源所有权；以实测能力表控制开放范围。
3. 再选择一个使用控制器或模型重绘的效果，定义其参数、对象绑定和执行顺序，不能把全屏支持泛化为模型效果支持。
4. 对每种协议分别验证导入拒绝、着色器编译、目标纹理输出、GL 状态、重载和实际游戏画面；完整 Ray-MMD 的多光源、环境光与后处理需另行设计和验收。
