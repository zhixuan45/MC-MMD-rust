# 1.21 深度格式兼容与描边遮挡修补

基线：`feat/1.21.1-neoforge`，`9a9cb88870925bae396dea7b4ea5c87a4d0acb56`。
修复分支：`fix/1.21-depth-format-outline`。没有修改或合并到 1.20，没有改模型、贴图、物理或原生库。

## 已定位与修改

- `ToonTransparencyLayers` 和 `OutlineCoverage` 原先只接受 sized depth format。驱动可将 Minecraft / 光影目标纹理的 internal format 报告为 `GL_DEPTH_COMPONENT` (6402)，导致透明分层和描边覆盖率采样分别回退。
- 新增共享 `DepthAttachment`，查询实际深度/模板位数、component type、尺寸、采样数、附件类型；按实际存储解析 unsized 格式，保留原始值用于日志。**没有将 6402 固定映射到 D24**。本轮 Mesa 实际报告 32 位 unsigned normalized，即 D32。
- 两个调用方检查深度 blit 的 GL 错误，不能只凭完整 FBO 宣布可用。透明分层在发布 ACTIVE 前用一个像素验证复制；完整深度副本仍在不透明模型画完、第一层剥离开始前更新。失败时恢复状态并回退，不用旧深度继续绘制。已有 GL error 也不会被清空后误报成功。
- 支持 D16；删除共享池在等大/较小目标切换格式时无条件拒绝的分支。格式变化会重新分配，避免 GUI/世界格式不同后一直回退；频繁格式切换仍有分配开销。
- 透明诊断 schemaVersion=2，保留 depthFormat 原始值，增加 resolvedDepthFormat/depthBits/stencilBits/componentType/attachmentType。复制失败报告 DEPTH_COPY_FAILED。描边回退日志增加原因与实际附件描述。

## 关闭深度补写后的描边

当 `toonDisableDepthSeal=true`（包括 JVM 覆盖）且描边内部目标可用时：

1. 复制场景深度到原有的 2×2 描边内部目标。
2. 用零外扩的原始模型几何补充**内部**遮挡深度，包含没有开启描边的材质，保留材质 Alpha、贴图遮罩、材质裁切阈值和双面标志。
3. 半透明按四个子像素覆盖率近似，不把所有低 Alpha 发片都变成完整遮挡墙；实际描边仍使用原颜色及 Alpha。
4. 绘制描边并合成颜色；内部深度不会写回场景，不影响“关闭深度补写”开关的含义。

这是四子像素量化的覆盖率近似（0/25/50/75/100%），不是任意层透明的精确描边透射；多个半透明表面共享样本也不是精确的 transmittance 乘积。低 Alpha 与移动时的稳定性仍需真实模型验收。正常深度补写开启时不增加这一模型重绘。

不支持的目标（默认 framebuffer 0、MSAA、启用 stencil/logic op、没有 DSA 的未知纹理目标、超出预算、复制失败等）仍保持直接描边并警告。此回退没有独立遮挡缓冲，因此在关闭补深度时不保证消除内部描边覆盖。没有通过禁用描边、强制不透明或抬高主体 Alpha cutoff 隐藏问题。

## 本轮实际验证

环境：Linux，Java 17 + ECJ，Mesa 25.2.8 软件 OpenGL 4.5 / EGL surfaceless。没有完整 Minecraft Java 21 构建环境。

直接编译并运行生产 `DepthAttachment`、`ToonTransparencyLayers`、`ToonTransparencyDiagnostics`、`OutlineCoverage`、`OutlineGlState`、`ShaderCompiler`、`OutlineRenderPass` 与实际描边 GLSL。独立测试的 Minecraft RenderSystem/设置/帧时钟使用最小适配；绘制循环集成检查使用直接转发真实 GL uniform 的 ToonShaderBase/ToonConfig 适配。**这些不是完整客户端或实际 BSL 调用链测试，也没有编译完整 ToonShaderBase 类。**

| 检查 | 结果 |
| --- | --- |
| 原版式 unsized 6402 纹理 | 实际 D32，8 层启用、深度复制、描边采样通过 |
| D16 / D24 / D32F / D24S8 / D32FS8 / 切回 unsized | 通过；切换格式没有池冲突回退 |
| begin 后新增不透明遮挡 | 第一层读取到新增深度 0.25，没有使用 begin 时的旧深度 0.8 |
| 描边独立深度 | 内部可写，宿主深度逐像素保持不变 |
| 实际描边 fragment 的 Alpha 0/.043/.25/.5/.75/1 | 四子像素覆盖计数 0/0/1/2/3/4，孔洞保留 |
| 实际 OutlineRenderPass，非描边前景遮挡后方白描边 | Alpha 0/.5/1 对应后方白色 1/.50196/0，宿主深度始终 1 |
| 不匹配深度格式 blit | 被检测为失败，没有误报成功 |
| 生产路径 GL error / FBO、VAO 恢复 | 通过 |
| 修补前对照 | 原 ToonTransparencyLayers 在 unsized 测试失败；原 OutlineRenderPass 在 Alpha .5 时白色为 1，覆盖率检查失败 |

新增 `DepthAttachmentGlProbe` 并接入 Linux 透明探针脚本；扩充 `DepthSealOutlineGlProbe`，检查独立覆盖、无描边材质遮挡与宿主深度不变；新增纯解析 JUnit 用例。

完整 Java 21 构建、全部既有探针、Windows GPU、杏辞动画以及实际 BSL / NeOculus 画面仍待验证。没有提供游戏 Jar，也没有将软件 GL 通过视为原截图完全修复。

```sh

# 提供平台 LWJGL natives 和 DISPLAY 后：

```

## 最短游戏复测

1. 用该分支的对应平台构建。保持透明材质与描边开启，先恢复深度补写，透明层数设为 8。
2. 开启 GPU 日志，确认 `[MMD透明分层]` enabled=true、actualLayers>0、resolvedDepthFormat 非零。depthFormat=6402 本身不再表示失败。记录 reason 与 remainingFragments。
3. 固定杏辞左右发尾/刘海的镜头和动作，比较无光影及 BSL；之后单独开启“关闭深度补写”，检查内部白覆盖、真实镂空、脸和衣服遮挡。
4. 只有实际启用分层且 remainingFragments=true 时再比较 8/16。保留 128 MiB 上限和原配置值；2560×1440 请求 16 仍可能只有 8 层，没有擅自提升默认质量和显存预算。
5. 若分层 ACTIVE、无剩余片元但仍有三角块，继续定位主体/描边/BSL 后处理，不以加层数宣布修好。“全体穿透”不是本轮已经证实的原因。
