# 头发蝴蝶结抖动：补充检查计划

2026-10-15。用户最新确认：S 形是模型自身表现，图中的肩侧碰撞正常；异常为蝴蝶结抖动，而且只在游戏中出现，TransformView 中没有。此前把侧向持续支撑视为异常的判断撤回。原身体网格接触替换提案停止推进，当前没有实施该架构，也不以减少肩部冲量作为修复目标。

## 当前证据

杏辞模型的左右蝴蝶结是独立动态刚体 #467/#468，关联骨骼 #575/#576，通过关节 #712/#713 连接后长发首节 #280/#286。两刚体质量 0.2，线性及旋转阻尼 0.999，原始允许碰撞掩码均为 0。关节允许局部 Y 平移 0～0.3，旋转范围为 X ±15°、Y ±10°、Z ±30°，没有平移或旋转弹簧。这些是作者数据，不据此认定阻尼、限位或质量有错；编号只用于样本诊断。

原始掩码不支持“蝴蝶结直接撞肩所以抖”的结论。需检查有效碰撞规则和实际接触，区分头发首节通过关节传递的振荡、约束限位、MotionState 插值和最终骨骼显示。用户报告构成动态现象证据，单张截图不能反映抖动频率或内部阶段。

现有侧转、移动、摆臂实验只证明发链存在肩侧接触，以及部分参数能改变接触结果。非零向上冲量、外推角度、肩壳到皮肤的间隔、停止后保持 S 形，均不能单独证明引擎错误。原先每 0.25 秒或更稀疏的快照不足以分析逐帧抖动，不能把窗口峰值当作持续振荡轨迹。

## 检查顺序和修改边界

先保持当前模型、开发物理配置和全部作者饰品参数，使用真实 idle/walk 动画，分别运行左右转头保持及回正、移动摆臂后停止、单独摆臂、纯待机和重置。对照 60/144 FPS，记录实际物理步号及零步帧；不能用转头结果代替移动触发。

探针增加可选 `--watch-body <名称片段>`，只记录匹配刚体和直接关节另一端，便于逐渲染帧采样。同步记录 Bullet 求解姿态、MotionState、根据最终骨骼与绑定 offset 重建的刚体姿态、父子相对变换、角速度、关节角度/越界量/锚点误差、最后子步的接触，以及对应 CPU 蒙皮代表点。名称仅作诊断选择，不赋予饰品头发兼容或几何代理资格。新增代码放在独立 `probe_hair_runtime/watch.rs`，不改生产物理求值。

若求解姿态的父子相对量已高频振荡，优先核对关节 frame、限位和父节点输入；若求解平稳而 MotionState 抖，检查固定步与插值时序；若前两者平稳而最终骨骼抖，检查回写顺序、非物理父骨刷新和动画覆盖；若 CPU 骨骼/蒙皮均平稳但游戏仍抖，再查 GPU 蒙皮及同帧姿态提交。每种结论都需同阶段数据支持，不预先选定根因。

确认差异后只修复对应通用缺陷，不按杏辞名称或编号特判，不统一增阻尼、锁住蝴蝶结、缩肩、关碰撞或添加向下力。若证据要求跨层架构替换，另出明确方案审阅；当前检查不恢复原网格接触替换提案。

## 验收

修复前后使用同模型、动画、相机、配置和帧率对照。验收目标是消除游戏中特有的蝴蝶结异常抖动，保留作者 S 形、自然摆动和正常肩/手臂阻挡。同时检查左右饰品、移动与转头、停止及重置，并选取其他带物理饰品的模型回归。

逐帧数值用于定位阶段，不能代替游戏录像；未修改生产代码和未完成游戏对照时，均不报告“已修复”。证据保存在 `Logs/hair-shoulder-20261015/`，正式复验入口与检查记录跟随验证文档更新。
