# 通用头发物理检查与修复计划

状态：原计划经用户批准进入实施，已完成逐点接触诊断、实验几何代理、完整运行探针，以及默认保留作者头发关节参数的候选。2026-10-15 用户最新确认：S 形为模型自身表现，肩侧碰撞正常，异常是仅在游戏中出现的蝴蝶结抖动。当前以该澄清为验收依据，下文原始浮空假设仅保留调查历史，不继续作为修复目标。保留原始 PMX 文件。

第二轮更新：已核实开发客户端加载候选 DLL，侧转保持采到后长发首节与肩部持续接触。用户最新正常参考说明，这些接触和 S 形不能作为缺陷证据；此前据此优先提出身体网格接触替换的判断撤回，该架构未实施，停止推进。蝴蝶结的独立动态刚体、关节传递、物理插值和骨骼回写成为当前检查重点，执行边界与验收见 `side_contact_implementation_plan.md`。诊断用自由轴和 0.7 肩壳倍率不交付为修复。

实施更新：用户补充实际在开发环境测试，尾发靠近手臂后被顶开。开发环境实际配置为 STABLE、自动身体壳开启、静态倍率 1.0，与前期外部实例不同；后续动作复验改用开发配置。独立手臂接触实验分别恢复发根、子链、全部作者约束，支持引擎额外单向限位与子链兜底共同放大接触的判断。因此第三阶段已进入候选修正，默认不再添加头发单向限位、20°/14°兜底和弹簧；`MMD_HAIR_JOINT_COMPAT=legacy` 保留旧行为对照。几何代理对该触发改善有限，仍由 `MMD_HAIR_COLLIDER_COMPAT=geometry` 显式实验开启，不能称为已验收的主修复。详细证据和交付边界见 `doc/physics/HAIR_CONTACT_FIX_VALIDATION.md`。

## 目标与当前证据

当前目标是定位并消除游戏中特有的蝴蝶结异常抖动，保留正常肩侧碰撞、作者 S 形及自然摆动。下文的几何、链条假设均须服从最新正常基线，不能凭外推角度、冲量或形状启动自动修正。

本轮洛天依杏辞审计已确认长发与袖子存在接触冲量、带向上分量的接触法线及末端持续支撑；上段胶囊半径为 0.3，末端球体半径却为 1.0、1.5。现有流形摘要的最大冲量与法线不保证属于同一接触点，所以向上冲量大小还需逐点取证。试验缩小球体显著改变外撑和下垂，但尚未检查完整网格覆盖，因此 **0.3 只是实验条件，不是通用修复值**。仅关闭肩部接触或跳过头发约束兜底，对固定待机的最终姿态影响很小。现有探针没有重现截图幅度的 S 形，源码测试的二进制也未与游戏实际加载库匹配。

通用方案分两步：先把异常时刻的接触、约束和骨骼显示对应起来；证据成立后，优先修正与发束几何明显不匹配的碰撞代理。约束或阻尼只有被独立对照证明导致异常保持时才调整，不把所有候选同时改动。

## 第一阶段：建立可重复的运行证据

复验先记录资产、VMD、配置和实际加载 DLL 的哈希。扩展本次探针，使它走完整 `MmdModel` 动画、物理和骨骼回写流程，连续播放实例中的待机与移动 VMD；加入明确可重复的转头、摆动、停止和物理重置序列。保存模拟刚体、MotionState、最终骨骼及对应网格的位置，区分物理链真正抬起与回写/显示造成的形变。已有统一前向速度扰动继续只作控制，不当作游戏动作复现。

在现有调试开关下新增头发专用采样通路。按已缓存发链集合筛选接触，而不是从全模型最强的五对接触中碰运气。记录另一端部位、接触点、法线及向上冲量分量、穿入、峰值发生时间，连同相邻关节角度、原始/有效限位、弹簧、锚点误差、限幅前速度及本帧实际子步数。有限采样和截断必须明确标注，未列出接触不能等同于不存在。

诊断默认关闭，关闭时不遍历发链接触、不增加 JNI 请求；打开时按物理步聚合，沿现有日志端口限频输出。接触方向统一到“作用于头发”的方向，避免 A/B 顺序反转后把向下法线当成向上冲量。一次构建缓存分类，不逐帧扫描名称或网格。

现有 `bw_world_copy_contact_manifolds` 的冲量来自最大冲量点，点位/法线来自最深穿入点，不能直接组合计算方向冲量。补充独立、有数量上限的逐接触点读取接口，在同一记录中返回刚体对、步号、点位、法线和该点已施加的法向冲量，必要时分别记录摩擦冲量；沿实际 `normalWorldOnB` 方向计算头发侧的法向冲量分量，并明确它不等于完整外力。保留旧流形接口/布局，Rust/C++ 新接口同批编译和测试，不顺手更改 Java JNI 签名。

阶段产物为同条件录像、时间窗日志和可复验脚本。若真实接触与截图位置不符，先沿当前骨骼回写和姿态时序继续定位；此时不把碰撞几何修改作为生产修复。

## 第二阶段：按发束几何生成保守的碰撞代理

识别资格同时使用刚体/骨骼名称、真实父子链和绑定网格，支持 PMX 模式 1 与模式 2。名称只是候选入口，不能凭“毛”“尾”或英文别名直接获得修正资格。明确排除尾巴、身体壳、袖子、裙摆、头饰和发饰；真正参与发链的节点应有可解释的网格影响区域。识别不改变现有尾巴受力或裙摆过滤规则。

在模型初始化阶段，从原始绑定顶点、BDEF1/BDEF2/BDEF4/SDEF/QDEF 权重、面片连通性和关联骨骼提取各段发束覆盖。SDEF/QDEF 保留真实权重语义；不能把当前蒙皮结果、待机姿态或整体头部网格用于永久拟合。混合权重边界需纳入相邻段覆盖检查，避免只取高权重点后漏掉发束边缘。

加载器中的顶点/骨骼是右手坐标，PMX 刚体和 Bullet 是左手坐标。几何比较先统一手性，再转换到有效刚体绑定局部空间；用刚体绑定逆变换做往返验证，避免把 Z 反转或 offset 错误误判成碰撞体过大。现有有截断的材质/权重诊断仅作候选线索，不能直接作为拟合数据全集。

先审计原始形状、发束横向厚度、纵向长度、邻段形状及原始球体的空余覆盖。用真实资产统计确定“明显不匹配”的资格阈值，记录来源并固定回归；不预填统一半径、统一缩放倍率，也不将高阻尼或单个大球本身视为错误。正常体积和作者有意制作的宽大末梢保留原状。

对有充分几何证据的候选，比较两种保守代理：仍能覆盖该段网格的较小球体，以及沿发束纵向的胶囊体。细长末梢若无法由小球完整覆盖，优先验证胶囊，不能为了下垂效果把碰撞覆盖裁掉。拟合使用覆盖所需的边界尺寸；Bullet 的真实 margin 纳入覆盖与接触验证，不能重复加入或忽略它。第一轮只扩大到已证实的动态长发末端球体问题，不顺手重建全部头发形状。

无可靠权重、无有效网格、分类冲突、非有限数据、分支/环链、多个不同刚体共用一骨且无法分配网格时，保留原始代理，并输出跳过原因。没有网格上下文的底层构建入口也保留原行为。头饰与头发共用材质时，材质名不能代替拓扑和权重资格检查。

实现采用运行时有效代理描述，保存原始索引、原始形状/尺寸/绑定变换和有效形状/尺寸/绑定变换，不改 PMX 文件或永久作者数据。尺寸、中心或旋转变化必须在创建 Bullet body 前统一决定。若中心/方向变化，用有效绑定变换重算 body offset 与约束局部 frame，保持原骨骼绑定关系和作者定义的世界关节锚点；不能仅换 shape 却保留不匹配的 offset/frame。

质量保持作者值；惯性张量按实际代理重新计算，这是形状变化的物理影响，必须纳入动态对照。刚体模式、原始双向碰撞掩码、关节连接、身体壳及裙摆规则保持原有契约。Strict/Stable/Relaxed 的掩码与禁碰规则不因形状修正被放开；几何兼容作为独立策略验证，不能依赖把用户切到另一模式来隐藏异常。

代理计划只在加载或相关物理重建时计算/应用。调试日志显示原始与有效参数，实际接触诊断、保守 AABB 和物理构造均使用同一份有效数据。保留一个开发用旧代理对照入口，切换经过重建和重置，而不是每帧替换 shape；本轮不新增设置页面或跨 JNI 签名。

Viewer 当前从原始 PMX 重算碰撞线框。接入修正后改为读取实际有效形状及其刚体姿态；物理未创建时明确显示原始预览。物理存在时不得用原始骨骼近似姿态冒充 Bullet 模拟姿态，同时明确选择模拟或 MotionState 渲染时间相位。

## 第三阶段：仅在证据要求时修正链条恢复

几何修正先单独做 A/B。若发链仍在离开接触后保持异常角度，按同一输入分别验证当前头发根/链弹簧兜底、原始限位和阻尼；先区分仍有其他部件支撑、关节撞限位、平衡点不正确、真实刚体已经回落而骨骼显示仍抬升。

当前根部兜底和链节兜底会改写无弹簧宽限位头发，但本次跳过兜底的结果没有证明它是主因。因此不预先全局降低刚度、放大限位或统一降低阻尼。若确认某条兼容规则造成恢复问题，再按链几何、质量和已观测行为收窄其适用资格，保留作者原有非零弹簧与合理限位；模式 2 必须单独验证父层级位置和刚体旋转的对应关系。

若证据指向坐标/回写或时间步缺陷，修复该缺陷并重新评估是否还需要几何兼容。任何新增向下力、逐帧强制归位、接触后清速度、全局关闭身体/袖子碰撞，均不能作为本计划的替代实现。

下列新增模块名为计划中的职责划分，实施时核对现有代码再确定签名。优先复用既有端口；需要跨模块传入绑定几何与有效代理，但不扩大成全库碰撞架构重构。

| `rust_engine/src/model/runtime/physics.rs` | 在绑定姿态构建代理计划，物理首次创建与重建应用相同计划 |
| `rust_engine/src/model/hair_geometry.rs`（新增） | 权重/连通网格收集、发段几何、歧义与覆盖报告 |

| `rust_engine/src/physics/mmd_physics.rs`、`mmd_rigid_body.rs` | 接收可选代理上下文，创建一致的 shape/offset/AABB；旧入口保持原行为 |
| `rust_engine/src/physics/mmd_joint.rs` | 核对有效刚体绑定变换到局部 frame 的映射，保留原世界关节锚点 |

先完成诊断与完整运行复现，再完成纯几何资格/覆盖测试，然后接入有效代理与真实 Bullet 接触，最后决定是否需要调整链条恢复。跨文件修改前核对构建、初始化、重建和诊断的完整调用链。分配只读追踪/测试与实现子任务时使用 Luna，明确禁止衍生新对话或子代理，避免多人修改同一文件。

工作区已有球面纹理、透明渲染和裙摆兼容等未提交改动，全部保留。根目录已有另一项尾巴—裙摆 `implementation_plan.md`，本计划独立保存，不能覆盖它。当前 `mmd_physics.rs` 为 946 行，新增实现进入子模块；任何改动代码文件超过 1000 行必须拆分，注释只说明关键边界。

## 验证、验收与交付

单元/几何验证覆盖五种权重形式、混合权重边界、镜像发束、不同模型尺度、正常大末梢、发饰、无网格/坏索引/非有限数据、共享骨骼及分支链。断言被接受的代理覆盖其目标网格；被排除的部件保持原参数。比较原始文件哈希与原始作者数据，确认运行时计划没有污染它们。

真实 Bullet 验证覆盖允许与禁止的双向掩码、三种稳定模式、模式 1/2、肩/上臂/动态袖子/裙摆接触、接触后释放、30 秒静置、不同渲染帧率和重置/重建。检查接触对、穿入、向上冲量、约束误差及恢复轨迹；速度限幅未触发或最大穿入下降，不能单独代表修复成功。有效代理中心变化后，初始世界锚点与作者定义一致，绑定姿态 offset 往返无新增偏移。

原生层至少执行 `cargo check --manifest-path rust_engine/Cargo.toml` 和与本改动有关的真实测试；若修改 Java/JNI，再执行对应 Gradle 测试与双平台编译。检查过滤器实际命中的测试数量，零项不能算通过。构建后核对交付 Jar、Windows 原生库及游戏加载日志的哈希，确保画面试用的正是本轮代码。记录构建环境和阻塞，不删除共享缓存或终止无关构建。

游戏验收以用户指定模型为首例，保持同一动作、相机、光影和物理配置，比较移动摆臂与转头后的左右蝴蝶结录像。应消除游戏中特有的异常抖动，保留作者 S 形、正常接触挤压及自然摆动；不以减小外推角度或消除向上冲量作为通过标准。

通用验收还必须覆盖实际可取得的正常长发、不同尺度/命名的长发、模式 2 长发及带发饰模型。样本先审计再选定，缺少某类真实资产时明确保留该类未验收，不用合成测试冒充游戏通过。完成这些对照后才把高可信候选的自动修正作为通用默认行为；不合资格模型仍原样运行。

交付包含代码变更、最小复验入口、原始/有效参数清单、测试结果、配套构建与剩余边界。固定条件游戏 A/B 尚待用户在重新启动后的开发客户端完成；离线探针不能替代该验收。
