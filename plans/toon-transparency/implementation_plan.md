## 当前证据与范围

用户报告杏辞长发末端出现随视角变化的浅色三角块，使用 BSL 10.1.8 和三渲二。实际长发材质双面、贴图包含半透明像素、没有球面贴图。当前 CPU/GPU 按三角形中心深度排序，不能正确处理同一屏幕区域内前后关系交叉的透明面。

目前尚未用截图对应的姿态和相机复现这一候选。已检查的排序方向、稳定平局、索引与材质行映射没有发现足以归因的局部错误。不得将以下方案或合成探针通过写成截图根因已确认。

“禁用透明材质”是用户另行要求的对照选项，默认关闭。开启时只在三渲二主体中将可见半透明像素按不透明绘制，完全透明像素仍裁切；保留材质，不改 PMX/贴图/物理。该选项独立实现和验证，不充当透明排序修复。

## 拟实施方案：局部深度剥离

先增加一个两片相交透明三角形的独立像素参考测试，令三角形在屏幕左右两侧交换前后关系。参考颜色按各像素的真实深度排序计算，不调用生产排序器。随后导出杏辞长发网格做同一姿态、多视角对照，区分透明错序与背面照明。

确认透明错序后，在现有三渲二透明 pass 内增加深度剥离作用域。沿用原包照明、纹理、材质和 MRT writer，逐像素收集透明层的深度，再按由远到近的层序重新绘制颜色。颜色仍写回原目标并沿用原有混合规则，避免把 BSL/Complementary 的不同输出编码混进通用颜色合成器。实心像素 pass 和模型最终深度补写继续使用现有流程。

实现复核补充：每层使用 R8 标记实际存在的透明像素，不能仅凭复制的不透明深度判断该层有效；遮挡查询只用于性能提示，不承担逐像素正确性。补充不透明背景与半透明面共面、不同像素透明层数不同的独立混合参考。

为响应用户追加的性能要求，原型默认 4 层，允许通过 JVM 属性设为 1～8 层；共享深度池硬预算为 128 MiB。这些是工程上限，不是实测需求。超过层数的深层部分保留原排序绘制，再绘制已剥离的近层；必须明确测试和报告此限制，不能宣称任意层数完全正确。按目标尺寸复用一个共享深度池，仅在存在可见半透明材质时工作；不在每帧分配纹理，不做 CPU 像素、位置或查询结果回读。深度阶段跳过照明，已选层按原材质提交，避免把全部排序 runs 重放多次；使用非阻塞条件绘制跳过空层。记录额外 GPU 时间、draw 数与显存，测量后再决定生产默认策略。

## 影响文件与状态契约

新增 `render/material/ToonTransparencyLayers.java` 管理分层深度目标、资源复用和释放，新增独立的小型状态作用域保存 FBO、viewport、draw/read buffers、纹理/sampler、depth/cull/blend/color masks；避免让 `SubMeshDrawHelper.java` 堆积资源管理代码。

`SubMeshDrawHelper.java` 接入剥离和颜色重放；`ToonShaderBase.java` 与 `toon_main_body.frag.glsl` 增加上一层/选中层深度筛选。`TranslucentBatchSubmission.java` 允许现有材质批次在各层重复提交，CPU/GPU 蒙皮均沿用同帧已有的几何，不重复推进动画或物理。

仅启用已验证的三渲二输出 profile。普通 Iris 实体、阴影通道、未知 profile、功能不足或创建失败时保持现有路径，并给出有界诊断。任何正常/异常退出都恢复宿主状态；清理模型、切换光影或退出游戏时释放持有的资源。所有单文件保持不超过 1000 行。

## 验证与交付

验证两片相交面在多个视角、不同提交顺序下的每像素混合结果；覆盖 alpha=0、半透明、实心、材质 morph、双面、CPU/GPU 与批量/普通提交。验证切回旧路径、开关恢复、FBO/纹理/sampler/SSBO/深度/混合状态和异常清理。编译并回读 BSL 10.1.8 三维度主体/描边，再检查其他已支持的光影 profile。

最终游戏验收必须使用杏辞、同一姿态/相机/时刻的开关对照。记录透明效果是否保留、浅色三角块是否消失，以及 GPU/显存开销。若相交透明复现不能解释原图，停止扩大透明改动，转向独立的背面照明对照。
