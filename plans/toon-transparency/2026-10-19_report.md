## 最终实现

两个加载器的“三渲二”页新增：

1. `toonTransparencyLayerCount`：0～16，默认 4，保存后生效；0 关闭分层但保留透明混合。实际层数受 128 MiB 共享池预算限制，深层尾部保留原排序。
2. `toonDisableDepthSeal`：默认 false。开启只跳过半透明颜色混合后的深度补写，保留原颜色、Alpha 和实心深度；阴影与普通非 Toon 路径不使用此开关。它独立于“禁用透明材质”。

中英日文设置与提示同步。旧配置保持原默认，磁盘数量规范到 0～16。JVM 数量/关闭分层参数继续优先；新增 `mmdskin.toonDisableDepthSeal`、`mmdskin.toonTransparencyDiagnostics`。完整行为见 [渲染说明](../../doc/render/TOON_TRANSPARENCY_LAYERS.md)。

### 证据 1：固定容差导致漏层

旧实现将宿主 D24 深度采样值与原始 `gl_FragCoord.z` 用固定 `1e-7` 比较。颜色选择用绝对误差，下一层筛选用 `layerDepth + epsilon`；存储/采样量化及浮点加法舍入令两个条件不能一致分割片元。

独立两片参考中，近片窗口深度为 0.5，另一片 z=0.00000036 对应窗口深度约 0.5000001788。旧生产类与旧 shader 回读为：

```text
actual   = [0.04705883, 0.4,        0.07843138, 0.5 ]
expected = [0.24705884, 0.43137255, 0.11764707, 0.75]
```

远片既未进入选中层颜色，也未成为后续层，Alpha 从预期 0.75 变成 0.5；另有近深度场景会受提交顺序影响。不是仅凭两条生产路径相等判定，而是独立按照已知每像素深度计算 source-over。

最终修复使用一张同宿主格式的不透明深度副本继续做硬件遮挡测试，每层用 R32F+MIN 保存原始片元深度，按其位值精确选择和重放。空层为 2，远平面 1 仍有效。去掉 epsilon，也不需要原始三角形 ID 或扩大容差。相同原始深度按源 submesh/三角形顺序混合；这是显式稳定平局规则，不恢复数值不可区分的几何次序。

普通与批量片元 shader 来自同一主体源码；已选层仍使用原材质提交，尾部沿用原排序与合批。原光影 MRT writer 和颜色混合公式保留，MIN 只作用于内部 R32F 附件。

### 证据 2：共享池高水位错误回退

旧类先分配 1500²×8 层（90,000,000 字节），随后请求 2200²×4（96,800,000 字节），却保留历史 8 层计算扩容，因超过 128 MiB 返回 null，错误关闭了当前本可容纳的分层。

新类在历史组合不能容纳时重建为当前合法需求，实测：

| 请求 | 实际层数 | 新池逻辑字节 |
| --- | ---: | ---: |
| 1500²×8 | 8 | 81,000,000 |
| 随后 2200²×4 | 4 | 96,800,000 |
| 2200²×16 | 5（预算降级） | 116,160,000 |
| 随后 320²×16 | 16 | 6,963,200 |

两项代码缺陷均有修复前失败、修复后通过的探针证据；与原截图的因果联系仍须游戏对照确认。

### 诊断和状态

结构化原因码/快照包含启用状态、请求/实际层数、目标与池尺寸、深度格式、MSAA 样本、预算、分配字节及深度补写状态。开启 GPU 日志或专用属性后，状态变化最多每五秒输出一条。

真正的尾部颜色绘制包在异步 occlusion query 中，继承同一 Alpha/深度/裁剪/双面条件。只有 K 层之后仍有可见片元才报告余量，不以末层非空代替。查询环固定四项、仅 ready 后读取；源帧和提交序号随结果输出，异常的部分提交作废。结果从不参与当前帧裁剪。

## 性能与容量边界

共享池按 `宽×高×(原格式深度字节数+4×层数)` 计账；不透明深度每次模型透明阶段复制一次，R32F 纹理跨模型复用。深度采集跳过照明；没有新加顶点或像素 CPU 读回、动画推进、阻塞 GPU 等待。开启诊断会延迟读取小型查询结果。

固定 320²、两片相交面、3 次预热、24 次热缓存提交的最终软件 GL 采样如下。先执行当前套件，再单独运行旧实现；不是游戏统计，也不是长期重复轮次的性能结论。GPU timer 含驱动/提交间隙：

| 模式 | 旧 CPU / GPU timer (ms) | 新 CPU / GPU timer (ms) | 新池字节 |
| --- | --- | --- | ---: |
| 中心排序 | 2.729 / 2.772 | 2.720 / 2.741 | 0 |
| 1 层 | 4.721 / 4.774 | 4.549 / 4.599 | 819,200 |
| 2 层 | 7.536 / 7.600 | 7.161 / 7.224 | 1,228,800 |
| 4 层 | 5.826 / 6.301 | 5.920 / 5.938 | 2,048,000 |
| 8 层 | 6.210 / 6.304 | 7.159 / 7.310 | 3,686,400 |
| 16 层 | 不支持 | 7.514 / 7.560 | 6,963,200 |

没有声称无性能损失；8 层软件采样反而更慢。层数增加会增加深度采集和颜色重放提交。每次 K 层透明阶段有 K 次采集、1 次尾部、K 次颜色重放；空层仍有 CPU 命令提交，GPU 可用非阻塞条件绘制跳过。游戏中实际 draw 数请结合现有 `[MMD透明性能]` 的 DRAW_TRANSLUCENT/DRAW_DEPTH_SEAL 计数采集；本轮未测真实场景的提交数、GPU 显存驻留或多人性能。

## 最短游戏验收

1. 使用当前代码对应平台构建，记录 Jar/原生库哈希。移除会覆盖 UI 的透明相关 JVM 参数。选择杏辞，保持 Toon 开启、“禁用透明材质”关闭，两个 Alpha 阈值均为 0.001。
2. 固定动作时刻、镜头和分辨率，开启 GPU 日志，依次设置 0/4/8/16 层。检查 `[MMD透明分层]` 的实际层数和回退原因，关联 `[MMD透明余量]` 的源帧。请求 16 不代表实际得到 16。
3. 固定一个实际生效的层数，单独切换“关闭深度补写（对照）”。保存同姿态画面，观察三角块、描边/云/后处理是否变化。它保留半透明，不等同于关闭透明材质。
4. 分别覆盖无光影/实际光影包、左右发尾背面近景/轻转镜头/远近变化、静止/发尾弯曲/转身；核对发丝渐变、脸、衣料、袜子和描边。
5. 单模型与多模型分别采集预热后的稳定帧段，记录实际 GPU/CPU 时间、显存、提交数、配置和包版本。若无余量仍有色块，继续区分后处理/背面照明等剩余机制，不能只继续提高层数。
