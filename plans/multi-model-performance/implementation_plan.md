## 实施前的机制与缺口

- `RenderPriorityService` 已有显示数量上限、距离分档、动画间隔和物理数量／距离预算。当前配置 24／48 格分档、动画每 1／2／4 帧更新，物理最远 24 格，显示和物理上限均为 10。继续压低上限会改变显示或动态质量，不能作为本计划默认收益。
- `BaseModelInstance` 按绘制入口执行原生更新，第一人称已有 prepared pose 复用；其它多 pass 是否重复求值须计数确认。纸娃娃通过独立请求键创建实例，不经过世界距离调度，每帧独立更新。
- `GpuSkinningModelRenderer` 已按 geometry revision 跳过重复骨骼上传和 compute，`TranslucentDrawOrder` 也已缓存候选和同 revision 的 GPU 回读；但深度键、排序、索引构建／上传仍每次执行。相机或模型视图变化时重新准备是正确行为，不能仅凭 geometry revision 复用排序。
- `TextureRepository` 已按路径共享纹理并引用计数，不能把再做一层纹理缓存当作主要新方案。同资产不同实体的原生模型及 GPU 静态几何仍各自创建；动态姿态、morph、物理不能因为资产相同而共用。
- 加载协调器为单后台线程，GPU finalize 在 acquire 中同步完成。这解释加载瞬间可能发生的卡顿，不足以解释模型加载完成后的持续低帧率，因此暂不优先改加载线程数。

## 原定实施顺序

### 1. 实例／帧统计与精确复用

先引入真实渲染帧标识和模型／场景更新计数，拆出动画／IK、物理、蒙皮、透明准备、主体／描边和纸娃娃外层的手持物品／flush。区分优先级候选、实际绘制、实际求值、物理步进次数；采样关闭时不引入额外 JNI 计时或逐帧日志。

只对同一实例、同一渲染帧且求值输入未变的结果复用原生求值。TaCZ 提交新目标后的强制再求值、VR、第一人称 prepared pose、暂停和阴影顺序必须保留。不能简单以世界 tick 去重，也不能仅凭同模型文件名去重。

透明准备新增有界缓存：键包含几何及 UV 版本、原始／动态索引版本、候选资格、材质与 alpha／显隐、modelView／projection、pass 的裁剪与着色语义及资源代次。输入完全一致时复用深度、排序、EBO 和材质行映射；视图、姿态或资格改变即重算。此项帮助同帧重复 pass 或 LOD 停更且视图不变的实例；近距离持续运动或转动相机时命中有限，不预估普遍收益。

涉及 `RenderPriorityService`、`WorldRenderPolicy`、`BaseModelInstance`、`RenderPerformanceProfiler`、`TranslucentDiagnostics` 和 `TranslucentDrawOrder`。先完成此阶段并用多人场景取证，再决定后续投入顺序。

### 2. 将当帧透明准备保留在 GPU

按已有 `plans/translucent-rendering/implementation_plan.md` 推进最小执行边界和 GPU 深度键、筛选、稳定排序、索引与逐三角形材质行生成，继续消费当前有序合批。目标是减少每个实例的同步位置回读、CPU 索引构建和往返上传。

快速路径需要完整链路闭合，不能算完 GPU 排序又把结果同步回 CPU 规划纹理窗口。可先覆盖全部所需纹理能放入一个现有窗口的自有 Toon pass；多窗口、外部／未知 Iris 程序和能力不足时保留兼容路径。遵守原来的深度与平局序号、当帧姿态、透明 alpha、球面纹理、眼发光和裁剪语义。资源及屏障由 GL 实现负责，不用上一帧位置换取表面收益。

这一阶段直接覆盖不同模型／不同玩家，即使它们不能共享姿态也受益。它不消除动画、物理和像素叠层成本，实际优先级由阶段 1 的多人数据确认。

### 3. 同资产资源共享与纸娃娃专用复用

静态网格、骨索引／权重、原始索引和 morph 偏移可按资产版本、后端与资源代次共享；骨骼矩阵、物理、动态 morph 权重、蒙皮输出和视图排序保留实例所有权。需有显存／内存预算、引用计数、在途读取和异常／重载／退出清理，先测资源收益再判断是否影响帧率。

纸娃娃是同一玩家同一模型的特殊消费者，可共享完整的只读姿态／蒙皮输出，继续按 GUI 视角独立排序及绘制。共享前核对头眼语义、动画层、morph、VR、TaCZ 和模型配置；当前 Rust `SetHeadAngle` 忽略 world 标记，但眼睛追踪输入可能因视角不同而变化，不能默认两实例姿态一致。世界第一人称的隐藏 EBO 不能用于纸娃娃。源模型未渲染、无有效快照或输入不一致时回退独立实例。

先取得纸娃娃分场景更新时间，再决定姿态快照与阶段 2 的先后。30／60 Hz 离屏缓存只作为用户可选质量模式，不作为默认多人帧率修复。

### 4. 再优化调度

阶段 1 如证实预算浪费，再加入真实可见性／屏幕占比优先级、稳定滞回及动画／物理任务错峰。不能把优先级候选集合等同于视锥可见集合；可见性筛选需保守处理包围盒，阴影 pass 单独处理。物理降级不得反复销毁和重建世界；远近切换和暂停恢复要保证时间步与姿态连续。

独立实例动画／物理的并行调度放在准备、执行、汇合边界明确以后。当前同步 render 入口、实体状态读取、JNI 锁和 GL 资源访问不能直接搬到线程池。

## 验证与完成标准

固定构建、分辨率、相机、动作和模型，用 1／2／4／8 个世界实体，分别测相同资产和不同资产。先关闭纸娃娃测世界扩展，再固定 1、4 个实体开启纸娃娃。记录 HUD 回调帧间隔中位／P95、真实实例数、原生求值及物理步数、透明阶段、回读次数／字节、GPU 查询和显存；窗口分位数不混合成全局分位数。确认新优化确实命中，收益不能只由减少显示模型或降低质量产生。

阶段 1 验证同帧不变输入复用，强制输入改变／切换视图／材质／UV／动态索引必须失效；阶段 2 使用真实 GL 对照排序序号、颜色和深度，覆盖零候选、容量、多材质及回退；阶段 3 覆盖引用、释放、资源重载、第一／第三人称和纸娃娃完整部件。按所改模块执行必要测试，不重建或改动无关物理工作树。每阶段独立保留开关和基线，游戏改善以实测为准。

## 2026-10-16 代码实施结果

1. `RenderFrameClock` 由两个平台 `GameRenderer.render` 驱动，覆盖世界到 GUI 的真实帧。`NativePoseInputs` 跟踪原生输入代次；`FrameEvaluationCache` 仅复用同实例、同帧、同输入的求值，强制刷新和 VR 保留求值。切换动画会失效对应层的赋值记录，未知 port 保守处理。`ViewTranslucentOrders` 为世界、第一人称和 GUI 各保留一个有界缓存，核对几何、UV、索引、材质资格、视图及裁剪语义，视图交替不再互相驱逐。
2. `GpuTranslucentPreparation` 在 GL 4.3 下执行当帧深度、裁剪、稳定排序、索引／材质行收集和间接绘制。适用范围为 GPU 蒙皮、自有 vanilla Toon、实际候选所需主／球面纹理能放入一个 8 槽窗口的透明 pass。窗口按候选材质建立，原始材质纹理多于 8 张不再直接判定失败。生产链路不读取位置、排序结果或 indirect command；原始／动态索引有已知 CPU 数据及版本时直接消费，未知来源仍保守回读。多窗口、Iris／外部程序、能力不足或 shader 初始化失败时走兼容路径。仍为三角形中心排序，不解决相交透明面排序的固有限制。
3. `ImmutableGpuBufferPool` 按 GL 上下文、数据语义与内容共享原始索引、静态几何、骨索引／权重和 morph 偏移，默认池预算 256 MiB，超预算独立分配。引用计数负责释放，RAM／VRAM 只向一个存活持有者记账。原生模型、骨骼／物理／morph 权重、蒙皮输出、光照 UV、动态第一人称索引与视图排序仍按实例持有。纸娃娃现在只核对世界实例在本帧完成绘制、实体归属和 native 输入版本，直接复用已求值的头眼、动画、物理和蒙皮结果；不再构造独立 GUI 预期姿态，因此局部眼睛／头部差异不会触发第二次求值。固定模式只改变 GUI 根显示朝向，跟随模式保留整体朝向跟随。源未绘制、输入版本过期、外部骨骼／IK 控制、VR、舞台播放或第一人称缺少完整身体索引时回退独立实例。
4. `AnimationUpdateSchedule` 用稳定句柄相位分散中远距离更新，保留配置中的 1／2／4 帧频率，距离边界使用 10% 滞回。优先级加入屏幕投影面积、相机朝向、上帧入选滞回和 UUID 平局顺序；物理距离预算加入 10% 退出滞回。没有新增模型硬裁剪，没有降低原有显示数量上限。
5. `PlayerWorldEvaluationPrepass` 在实体绘制循环前收集至少两个合格远端玩家 GPU 模型，渲染线程准备输入，最多三个工作线程加调用线程执行 JNI，全部汇合后在渲染线程发布结果。遵守实体冻结的 partial tick、可见性和区块检查，不触发模型加载。相同句柄去重，常规失败仍等待其余任务。排除本地玩家、VR、TaCZ、舞台及外部姿态；Iris 主世界实体程序也可使用该 CPU 预求值，平台注入在阴影 frustum 下不调用且运行时保留阴影保护。关闭同帧复用也会关闭预求值，防止重复执行。
6. 纸娃娃增加每帧／60 Hz／30 Hz 选项，默认每帧。60／30 Hz 使用独立深度的 RGBA8 离屏目标、预乘 alpha 合成和 128 MiB 预算；刷新成功才记账，尺寸／布局／模型／模式改变会失效。手持物品、光影包、特殊 stencil／logic／sRGB／MRT 或独立 draw-buffer 状态回退每帧。释放与资源重载、隐藏及退出接通。

采样记录各场景实际绘制句柄数、求值／复用数、启用物理的求值数、主体／描边与纸娃娃物品／flush 时间。新 JNI 以 64 字节版本化 direct buffer 返回动画、IK、物理、CPU 蒙皮的独立时间及 Bullet 实际调用／执行子步／请求子步，旧 DLL 无入口则回退常规求值。GPU 求值的 CPU 蒙皮时间为零，采样关闭不读取阶段时钟。`scene.NAME.physicsEnabledEvaluations` 仍只是启用物理的求值次数；实际步数应读新字段。并行 native 累计工作时间不能当主线程阻塞，需同时检查 `native.batchExecuteJoin`。GPU 查询仍覆盖原绘制作用域，不能作为纯 GPU 排序耗时。

### 对照开关

全部默认开启；在启动 JVM 参数中设置 `-D名称=false` 可逐项关闭。预算参数单位为 MiB。

| 名称 | 作用 |
| --- | --- |
| `mmdskin.reuseEvaluation` | 同实例同帧原生求值复用 |
| `mmdskin.parallelEvaluation` | 独立远端玩家模型并行求值；依赖 `reuseEvaluation`，不足两个合格模型保留常规入口 |
| `mmdskin.reuseTranslucentPreparation` | 输入完全相同的透明准备结果复用 |
| `mmdskin.gpuTranslucent` | GPU 透明准备与间接提交 |
| `mmdskin.translucentBatch` | 透明材质合批，包括 GPU 快速路径 |
| `mmdskin.paperDollReuse` | 纸娃娃共享本帧世界姿态与蒙皮 |
| `mmdskin.shareStaticBuffers` | 同内容不可变 GPU 缓冲共享 |
| `mmdskin.stableScheduling` | 错峰、距离滞回及朝向／上帧优先级；关闭后使用原距离分档与相对帧间隔 |
| `mmdskin.staticBufferBudgetMiB=256` | 共享池预算；0 时独立分配，最大 8192 |
