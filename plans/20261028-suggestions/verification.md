## 音频异常证据与修复

用户截图给出的源格式为 IEEE float32、44.1 kHz、双声道 WAV，异常仅在舞台播放出现。本次没有取得原始 WAV 文件。

用同类型合成样本复现旧 `AudioSystem` float32 → PCM16 路径：

| 输入 | 旧路径 PCM16 输出 |
| --- | --- |
| +0.99 | +32439 |
| +1.05 | -31131 |
| +1.5 | -16386 |
| -1.05 | +31130 |
| -1.5 | +16384 |

超出 ±1 的浮点峰值在转换中发生符号翻转，会制造波形突变。新解码保留有限浮点峰值，并向 OpenAL 上传 `AL_FORMAT_MONO_FLOAT32` / `AL_FORMAT_STEREO_FLOAT32`。8/16/24/32 位整数上转 float32，采样率和声道不变；上转不会凭空增加原文件的信息。非有限样本置零。设备不支持 float32 扩展时报告失败，不静默降为 PCM16。

32 位缓冲区也不代表最终声卡输出位深；最终设备混音及输出格式由 OpenAL/系统控制。

读取和转换在单独后台线程进行，进度按字节/样本更新；完成转换显示 95%，音频上传完成后到 100%。主持端先预加载，再开始并广播舞台；观演端若延迟完成，则从当前舞台帧对应时间播放。ESC、换场和清理会取消加载。

旧同步每遇 0.15 秒偏差就直接设置播放位置。新同步对小偏差做有限速度修正，对大跳转先淡出、定位再淡入，避免直接切断正在播放的波形。

## 界面操作

- 舞台选择页：开始时显示音频加载/处理进度；结束依据按钮可循环选择“沿用当前、镜头末帧、动作末帧、音乐结束、可用来源最短”。缺少所选来源时回到旧规则并记录日志。
- 表情轮盘：点击 `VPD` 打开直接加载列表。文件放入角色目录、`CustomMorph` 或 `DefaultMorph`。该页及轮盘均可“恢复默认姿势”，仅解除 VPD 骨骼覆盖；原有“重置表情”操作仍清除表情并解除 VPD 骨骼覆盖。进入舞台时解除 VPD 姿势，避免盖住 VMD。
- 模型设置：新增“道具物理”开关，保存后生效；全局关闭物理时，道具也停止物理演算。

## 程序验证

- Java：304 项测试通过，0 失败、0 忽略。新增检查覆盖 float32 超范围峰值保留、整数位深/字节序、非法浮点、异步预加载/取消、同步淡入淡出、结束来源回退、末帧先呈现、结束帧网络往返、道具同帧求值及物理开关。
- Rust：136 项通过、0 失败、2 项原有忽略；覆盖编码一致性、损坏姿势拒绝、VPD 恢复不清除外部输入，以及混合 VMD 的镜头/动作末帧分离。
- OpenAL Soft loopback：真实创建 float32 缓冲区，检查 `AL_BITS=32`。输入常量峰值 `1.25`、音量 `0.25`，渲染结果 `0.3125..0.3125`，保持正号和幅度。此验证不需要实际声卡，不等同于原文件听感验收。
- Fabric、NeoForge 的构建均成功；两个最终 JAR 均包含新增类、重定位后的 MP3 解码器，以及与本次构建一致的 Linux x64 原生库。已核对三个新增 JNI 符号。

正常 Java 21 JDK 环境下的复现命令：

```sh
cargo test --offline --lib --manifest-path rust_engine/Cargo.toml
bash gradlew --no-daemon :common:test :fabric:build :neoforge:build
```

云环境最初只有缺少启动器和 `ct.sym` 的运行时，本次在工作区补齐同版本 Debian JDK 文件；未修改工程的 Java 21 编译目标。NeoForm 下载使用临时启动参数，将清单地址选为允许访问的官方 `piston-meta.mojang.com` 入口，代理与证书验证保持生效。以上是构建环境处理，不属于产品改动。

## 产物使用范围

提供的两个预览 JAR **只包含 Linux x64 原生库**。按当前加载器选择其中一个，勿同时安装 Fabric 与 NeoForge 两个包。Windows/macOS 等平台须用同一份源码构建匹配的 native，再按既有 CI 打包；新增 JNI 接口要求 Java 与原生库一致。本次未构建 Windows DLL，也未进行 Windows 游戏验收。

源码补丁供审阅和后续跨平台构建。各产物 SHA-256、基线和补丁哈希记录在随包 `build-info.json` 中。
