# 屏幕空间材质近似实验计划

## 目标与判断

用户观察到 NiseMMD 在高负载下可能出现“远距离帧率高、近距离帧率低”，并指出兰序模型的珠子材质由许多约 5k 面的高面数网格组成，关闭该材质后帧率明显上升。本计划验证一种更窄的假设：当材质投影到屏幕后的覆盖范围很小，继续提交完整高面数网格的收益是否低于其 CPU/GPU 成本。

“实际画面分辨率”可以作为判断输入，但不能单独作为 LOD 依据。应结合相机视场角、模型深度、材质的投影包围范围、透明/裁切语义、球面贴图、描边和阴影 pass 计算屏幕空间尺寸。远处帧率上升也可能来自视锥裁剪、遮挡、透明过绘减少、更新频率变化或光影包内部策略，不能仅凭帧率曲线确认 NiseMMD 的具体实现。

## 当前代码边界

现有渲染路径已经具备透明候选缓存、Alpha Coverage、透明排序、GPU 透明准备和距离调度，但 `SubMeshDrawHelper` 接收的子网格记录主要是材质 ID、索引起点、索引数量、alpha、可见性和双面标记。生产路径尚没有稳定的“每个材质屏幕包围体”或“同材质低模索引缓冲”。现有 `setMaterialVisible` 是用户显式材质可见性控制，不能直接改作自动 LOD，否则会与第一人称和模型配置的可见性语义冲突。

因此不把运行时随机删三角形作为首个方案。任意抽样会破坏珠子的轮廓、UV 连续性、法线、高光、SPA/SPH 和透明排序，尤其不适合由多个透明面叠出的材质。

## 实验分阶段实施

### 阶段 0：固定条件基线

使用同一个模型、动作、相机、光影、窗口分辨率和视图距离，至少采集以下对照：珠子材质开启、关闭；单个模型、多个模型；世界主体、阴影、纸娃娃（如适用）。记录帧时间中位数/P95，并区分 CPU 主体提交、原生更新、透明提交、回读、GPU draw query。现有四模型记录已经显示 BSL 兼容透明路径可能退回逐 run 提交，因此必须确认珠子成本来自顶点/片元、透明 draw 数、阴影重复提交还是其它路径。

### 阶段 1：只读材质与屏幕覆盖率诊断

为每个材质/子网格输出一次静态摘要：材质名、三角形数、唯一顶点数、索引字节数、是否透明、alpha coverage、是否双面、球面模式、是否参与描边和阴影。运行时在固定采样窗口输出：投影包围球或 AABB 的屏幕直径/面积估计、视锥状态、实际 pass、实际 draw 数和提交耗时。

屏幕尺寸可用近似式计算：

`diameterPx ≈ 2 * focalLengthPx * radiusWorld / depth`

其中 `focalLengthPx` 由视口高度和垂直 FOV 得到。对非球形珠子，应同时记录投影 AABB 面积和最大投影直径；近裁剪面、负深度、非有限矩阵和超出视口时采用保守结果。诊断阶段不改变绘制结果。

阶段 1 的成功标准是能回答：开启珠子材质后，主要增加的是顶点处理、片元/过绘、透明排序与 draw 提交，还是阴影 pass；以及高成本材质在多少屏幕像素范围内仍然可见。

### 阶段 2：离线生成珠子低模候选

针对珠子这类重复、高面数、材质相对单一的网格，优先离线生成 LOD1/LOD2，而不是运行时删除三角形。低模必须保留材质绑定、UV、法线方向、双面标记、透明语义以及必要的 SPA/SPH 资源；如果材质依赖复杂 morph 或逐顶点变形，则先标记为不可替换。

候选低模至少包含：原始网格、保守低模、极简代理。每个候选记录三角形数、包围体误差、轮廓误差、UV 覆盖误差和材质差异。珠子可以优先测试 UV 球/近似球代理，但不能把这个特例直接推广到头发、睫毛、透明服饰或带强烈轮廓的网格。

### 阶段 3：默认关闭的屏幕空间选择器

在材质/子网格选择层增加实验性选择器，输入为投影直径或面积，输出为原始、LOD1、LOD2 或跳过。选择器只作用于世界场景；第一人称、库存、纸娃娃、物品和阴影先保持原始路径，避免把视图距离误用到不同场景。

选择器必须具备滞回：进入低模和恢复高模使用不同阈值，并以材质级状态缓存，避免模型在阈值附近闪烁。阈值不要在实现前凭经验固定，先根据阶段 1 的采样分布设定。默认关闭，可按模型或材质 allowlist 开启，并保留一键回退到原始网格。

跳过整个材质只作为最后一级、且仅适用于屏幕覆盖低于一个很小预算并且材质不承担轮廓、透明孔洞、眼部、脸部、发片或阴影关键作用的候选。优先使用低模代理；如果没有代理，应保持原始绘制。

### 阶段 4：固定场景 A/B 验收

使用相同模型、动作、相机、光影、分辨率和实体数量，对原始路径、仅诊断、LOD1、LOD2 分别采集至少站立/走路/跑步窗口。记录 FPS、CPU 主体提交、GPU draw、透明 draw、阴影 draw、显存和视觉差异。截图或录屏需覆盖近景、中景、远景、转身、高光、透明边缘和阴影；不能用离屏探针或构建成功代替游戏画面验收。

验收通过条件：远景或中远景的帧时间有稳定改善；近景珠子轮廓、高光、透明边缘和动画无明显跳变；阈值附近无闪烁；关闭实验开关后与基线一致；BSL、Complementary 和无光影路径均不出现状态泄漏。

## 推荐的首个实现切片

第一切片只做阶段 1 的只读统计和离线候选报告，不修改渲染结果。建议复用 `TranslucentDiagnostics` 的模型/场景作用域，在 `SubMeshDrawHelper` 或其上游准备阶段统计子网格三角形数和 pass；屏幕投影尺寸应从现有 model-view/projection 与当前视口读取。统计输出要区分“估计覆盖率”和“实际像素覆盖率”，前者不能冒充后者。

第二切片再为一个明确的珠子材质接入默认关闭的低模代理，先只覆盖 WORLD 主体 pass，并保留原始透明排序、球面采样和材质状态。确认近景/远景 A/B 后，才考虑扩展到阴影和其它材质。

## 暂不采用的方案

不直接按距离关闭所有高面数材质；距离不能表达 FOV、屏幕分辨率、模型缩放和视口大小。

不在 GPU shader 中按随机比例丢弃三角形；这会产生轮廓断裂、透明排序错误和驱动相关差异，而且不能减少顶点提交到足以解决 CPU/Draw 负担。

不把材质贴图分辨率当作几何复杂度的替代指标。贴图像素密度可用于 mip/采样策略，不能说明 5k 面网格是否值得保留。

不把 NiseMMD 的行为当作已确认事实。只有在固定条件下获得屏幕覆盖率、提交成本和 A/B 画面证据后，才能决定是否值得推广为通用材质 LOD。

## 审批边界

本文件只定义分析和实验顺序，尚未修改生产渲染逻辑。获得批准后，先实施阶段 1 的诊断切片；如果阶段 1 不能证明珠子成本与屏幕覆盖率相关，则停止 LOD 改动，转向透明提交、阴影重复或材质状态的独立优化。
