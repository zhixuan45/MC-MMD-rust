# 纸娃娃性能优化取舍

2026-10-15 根据本地代码和第一阶段日志制定，2026-10-16 更新。已在多模型优化中实现本帧世界姿态／GPU 蒙皮输出的条件复用和 GPU 透明准备；下文保留方案与日志分析。完整范围及开关见 `../multi-model-performance/implementation_plan.md`。头眼输入不一致、源未渲染、VR／外部骨骼控制等情况回退独立实例；GUI 继续独立光照、完整网格与视图排序。离屏缓存和刷新率上限尚未实现。

## 已观察

- `PaperDollRenderer.renderHud` 在打开 Screen 时返回；`renderInScreen` 仅处理暂停菜单类界面并排除原版背包，没有两入口每帧重复绘制的证据。
- `renderPaperDoll` 用 `ModelRequestKey.paperDoll` 获取独立 `ManagedModel`，独立调用 `AnimationStateManager.updateAnimationState` 和模型 `render`。它隔离 GUI/世界姿态及第一人称部件状态，也有独立动画、物理和蒙皮求值的成本；现有原生更新统计未单独拆分这些费用。
- 修复前 PAPERDOLL 平均约 10970 个透明候选、6282 个透明 draw；每调用 SUBMIT 约 5.736 ms、SORT 约 0.302 ms、INDEX_BUILD 约 0.703 ms、READBACK 约 0.862 ms。候选拓扑多数已命中缓存，继续缓存相同候选不是首要方向。

## 建议实施顺序

1. **测公共批量提交收益。** 本轮 vanilla Toon 的材质表提交已覆盖纸娃娃。先关闭测 WORLD，再开启测 PAPERDOLL；对照逻辑 runs、实际 draw、SUBMIT、整个模型调用和独立游戏帧间隔。
2. **补独立更新统计，再评估姿态复用。** 区分更新器、原生动画/物理、蒙皮、绘制、手持物品和 GUI flush。同模型且动画/morph 状态一致时，可设计只读完整姿态快照，明确版本、所有权和释放顺序；GUI 保留独立视图与透明排序。不能直接共享第一人称隐藏部件后的 EBO，也不能让 GUI 头眼状态覆盖世界实例。头眼、模型选项、VR 和暂停行为要有失效/回退条件。
3. **读回和索引生成仍显著时，再推进 GPU 排序。** 纸娃娃视角不同，不能直接复用世界视图的透明索引。符合条件时共享只读完整蒙皮几何，按 GUI 视角生成独立深度键与排序；配合主计划的设备接口和非阻塞同步，不能用旧姿态中心替代当帧几何。
4. **离屏缓存和刷新上限作为可选模式。** 将模型、描边和手持物品一起画到小尺寸透明目标，HUD 合成缓存纹理，可选择跟随主帧率或 30/60 Hz。限频会改变预览流畅度及延迟，应由用户选择。需要处理透明合成、深度隔离、GUI 缩放、位置/尺寸、模型/配置切换、资源重载及释放。仅把每帧绘制搬到 FBO 不会自动消除 CPU 提交和动画更新。

## 验收

同模型、窗口和世界状态配对比较关闭/开启纸娃娃，固定/跟随朝向分别验证。包含站立、走跑、受击/使用物品、暂停、背包、GUI 缩放、切换模型、第一/第三人称和 Toon/光影切换。测游戏帧间隔、纸娃娃更新成本、提交和 GPU 查询；对照发丝/裙摆、眼部发光、遮挡和手持物品。不能预估未实施方案的实际 FPS 增益。

## 22:42–22:47 新日志复核

2026-10-15 的本轮采集已包含完整性能记录。WORLD 和 PAPERDOLL 均为每调用 1 个实际透明 draw，`BATCH_FALLBACK=0`，确认纸娃娃命中合批。旗袍纸娃娃 id=43 在 22:46:49–22:47:04 的 1314 次调用中，READBACK、DEPTH_KEYS、SORT、INDEX_BUILD 加权均值合计约 2.41 ms，SUBMIT 约 0.512 ms。当前剩余成本包括每视图透明准备和独立实例求值，不能继续归因于几千个实际 draw。

同模型纸娃娃开启区间的 HUD 回调间隔明显增加，原生更新统计也增加，但尚无纸娃娃独立物理计时。用户随后明确优先改善多个模型同时显示的帧率；共同优化路径、统计边界和分阶段实施方案见 `../multi-model-performance/implementation_plan.md`。本轮尚无 2／4／8 个独立世界实体的性能数据，纸娃娃双实例不能直接替代多人基线。
