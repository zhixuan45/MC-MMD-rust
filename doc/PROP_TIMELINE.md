# 舞台道具帧控制与图形时间轴编辑器

独立 PMX 道具可以跟随舞台帧显隐，并在指定帧切换外亲骨骼。图形编辑器支持同一帧分别登记多根道具骨骼，自动计算保持当前姿态的相对补偿，同时保留完整 PMX、道具 VMD 和动态物理。时间轴保存于 VMD 旁的 JSON；旧版整模型挂载继续兼容。当前绑定目标为道具所属人物，跨人物外亲、多道具和事件轨道留待后续。

## 图形编辑器

在「模型设置 → 道具设置」中选择道具 PMX 和道具 VMD，点击 **编辑道具时间轴**。无需预先创建 JSON；没有配套文件时从默认显示、默认挂点开始编辑。已有文件加载失败时会显示错误并保留原文件。

界面左侧为角色和道具的 3D 预览，右侧为当前轨道的属性，下方为显隐与外亲两条轨道。

- **拖动定位**：点击/拖动标尺或任意一条轨道移动播放头；点击关键帧标记可定位该帧。帧号框支持直接输入；`-1` / `+1` 和左右方向键逐帧移动，Shift + 方向键每次移动 10 帧。Home / End 定位到首末帧，`<K` / `K>` 切到当前轨道前后关键帧。
- **播放预览**：点击播放/暂停或在输入框之外按空格，以 30 帧/秒播放；到末帧停止，再次播放从第 0 帧开始。
- **显隐关键帧**：选中显隐轨道，在右侧选择「显示/隐藏」，点击「在当前帧添加显隐」。当前帧已有关键帧时，按钮改为「更新当前帧关键帧」。也可以改变首个显隐关键帧之前使用的初始显隐状态。
- **外亲关键帧**：选中外亲轨道，先选择「扇子骨骼」，再选择或输入人物父骨骼，填写额外偏移和旋转。默认「保持姿态注册（自动补偿）」；也可切换为「对齐挂点」。选择「整个道具（旧版）」沿用整模型 `snap` 挂载。
- **同帧多骨骼**：登记第一根扇子骨骼后，保持帧号不变，选择另一根骨骼继续登记。每根骨骼分别保留自己的关键帧，同帧标记同时显示；左右关键帧导航和更新操作针对当前所选骨骼。轨道上的数字表示当前帧有效绑定数。
- **删除与解绑**：删除或 Delete 只删除所选轨道、所选道具骨骼在当前帧的关键帧，之前的绑定可能重新生效。「在当前帧解除所选骨骼绑定」写入解绑关键帧，从该帧恢复此骨骼的 PMX 原父级，其他骨骼的绑定保持有效。
- **视角与小窗口**：在预览区拖动旋转，滚轮缩放。右侧属性较高时可在该区域滚动，避免小 GUI 尺寸遮挡操作。
- **保存**：点击保存或 Ctrl+S 写入当前 VMD 旁的 `.timeline.json`。离开未保存的时间轴时可选择继续编辑或放弃修改。保存时间轴后，若模型设置里的 PMX/VMD 选择也有修改，返回模型设置点击保存。

「角色动作 VMD」可选择本角色目录/`anims/` 的 VMD，或 `StageAnim/<动作包>/` 中的 VMD，作为换手时机和注册补偿的参考。角色和道具共用当前帧号，较短的一方保持末帧；不选择参考动作时角色保持静止。参考动作标签保存于时间轴，下次打开自动恢复，不修改人物的动作配置。应选择实际演出采用的角色动作，保证登记补偿与演出姿态相符。

骨骼补偿同时保存来源校验：人物 PMX、道具 PMX/VMD、参考人物 VMD 的内容 SHA-256，以及参与挂载的骨骼、位移、旋转和模型缩放。播放时会检查这些来源，避免另一人物或另一段动作误用已登记的相对姿态。选择了参考动作时，当前人物演出应只使用内容相同的该段 VMD；多文件合并的演出不自动视为单段参考动作。若需要明确从模型静止姿态注册并跨动作使用，可选择「无（角色静止）」后重新登记。

来源不匹配时，该次舞台使用简单挂载，跳过不匹配的道具 VMD 和时间轴，并以 `[StageProp]` 输出一次原因；不会改写保存的设置或补偿。已有版本 2 文件缺少来源信息时，打开编辑器并保存一次，编辑器会重算补偿并补齐来源登记。版本 1 旧整模型时间轴不要求这项迁移。

修改早期外亲关键帧、删除绑定或切换参考动作后，后续注册补偿会标记为需要重算。可点击「按时间顺序重算全部补偿」；保存时也会先重算。重算按帧号及同帧登记顺序，在独立预览实例中逐条执行，全部成功后才替换编辑状态。修改 PMX、道具 VMD 或模型握持/缩放配置后，应重新打开编辑器；来源变化会自动标记补偿过期，保存时重算。来源校验只在打开、保存和会话绑定时读取文件，不在每次绘制中读取资产。

预览使用独立的角色、道具实例与动画句柄，退出或打开选择页时释放；拖动不会定位或覆盖世界中正在播放的角色/舞台。为使任意帧拖动可重复，编辑器预览关闭物理；游戏中的道具物理仍按模型设置执行。

保存保留原文件的对象 ID 和顶层/对象附加信息，按帧排序输出轨道。文件在编辑期间被其他程序修改或删除时会拒绝覆盖，需重新打开编辑器读取最新版本。正在播放的舞台不会热加载修改，重新开播后生效。

## 配置与文件位置

1. 将独立道具 PMX 放入角色目录，在「模型设置 → 道具设置」选择它。
2. 将道具专用 VMD 放入同一角色目录或其 `anims/` 子目录，在「道具 VMD」中选择并保存。
3. 将 [扇子示例](examples/fan.timeline.json) 复制到实际使用的 VMD 旁，文件名将 `.vmd` 替换为 `.timeline.json`。
4. 修改 `motion`、`asset` 和骨骼名以匹配本地文件，然后重新开播。

例如：

```text
EntityPlayer/角色/
  角色.pmx
  团扇.pmx
  anims/
    扇子动作.vmd
    扇子动作.timeline.json
```

对应的模型设置为：

```json
{
  "heldPmxFile": "团扇.pmx",
  "heldPmxStageMotion": "扇子动作.vmd",
  "heldPmxPhysicsEnabled": true
}
```

同名 VMD 优先选择 `anims/`，时间轴只读取被选中 VMD 旁的文件，不再回退到角色目录的另一份时间轴。运行中修改 JSON 后需要重新开播；没有配套文件时保持原有道具动作与挂点设置。

## 轨道语义

时间基准为当前舞台的 VMD 帧（30 帧/秒），从第 0 帧开始；与渲染 FPS 和 Minecraft tick 无关。角色和道具使用同一个舞台帧。短道具 VMD 到末帧后保持姿态，控制轨道仍继续按舞台帧求值。时间轴不会延长舞台，关键帧应放在舞台结束帧以内。

示例在 120 帧显示扇子，480 帧由 `右ダミー` 切换到 `左ダミー`，900 帧隐藏。关键帧在指定帧立即生效，并保持到该轨道下一关键帧；关键帧可以乱序填写。显隐和旧整模型挂载轨道各自不允许重复帧；骨骼外亲只禁止「同一帧 + 同一道具骨骼」重复，允许不同骨骼同帧登记。初始可见性默认 `true`，未指定外亲时使用已保存的道具绑定。

向前跨帧、向后定位、回到第 0 帧，以及道具延迟加载，都会根据目标帧求出应有的显隐与外亲，无需经过中间各帧。每位表演者拥有独立状态。外亲变化或向后定位会重置道具物理；物理仿真的历史不会由时间轴倒放，精确复现穗子摆动仍需从头播放。

舞台已绑定专用 PMX/VMD 时，即使主手没有 Minecraft 物品也会加载并显示道具。隐藏状态下跳过道具几何和阴影绘制，保留动作、挂载参考系和物理更新；不会因为扇子隐藏而显示原版主手物品。舞台外仍沿用主手有物品才显示 PMX 替换的规则。

## 旧版整模型外亲和偏移

每个外亲关键帧包含：

- `parent.object`：第一阶段固定为 `actor`，表示该道具所属角色。
- `parent.bone`：精确的角色骨骼名，例如 `右手首`、`左手首`、`右ダミー`；不会自动把这些名称视为彼此的别名。
- `mode`：省略或填 `snap`，立即对齐新挂点。
- `offset`：可选的三个局部位移，默认 `[0, 0, 0]`。
- `rotation`：可选的 X/Y/Z 旋转，单位为度，默认 `[0, 0, 0]`。

位移使用角色骨骼的模型单位，与已有道具偏移保持一致。时间轴的额外变换在模型设置中的固定握持偏移和旋转之后组合；两个偏移不会写回模型设置。外亲关键帧未填写额外变换时为零，不继承上一关键帧的额外变换。

```text
道具变换 = 角色骨骼变换 × 固定握持变换 × 时间轴额外变换 × 道具缩放
```

道具 VMD 继续在道具自身坐标内求值。渲染和道具物理共用同一份挂载变换，CPU/GPU 蒙皮共用控制状态。

也可以在 `initial.attachment` 中使用同样的 `parent`、`mode`、`offset` 和 `rotation` 字段，定义第一条外亲关键帧之前的绑定。

骨骼不存在时，道具在该绑定期间隐藏，日志以 `[StageProp]` 提示一次；后续切到有效骨骼后可以恢复。JSON 格式错误、资产名不符、重复帧或使用尚未支持的模式时，整份时间轴被忽略并记录原因，道具 VMD 仍按原流程播放。

## 多骨骼外亲与自动补偿（版本 2）

例如文档中的 3098 帧，可先登记 `全ての親 → 右ダミー`，再登记 `センター → 右ダミー`；3099 帧再分别登记 `全ての親 → 右ダミー` 和 `センター → 左ダミー`。之后增加 `センター補助1 → 右人指3` 时，已有其他骨骼绑定持续生效。在新帧重复登记相同目标也会创建新的注册补偿，不会因为目标相同而跳过。

骨骼名全部取自实际模型。团扇和折扇骨架可能不同，必须选择作者模型中实际存在的控制骨，不能把本地团扇骨骼直接当成折扇骨骼。

新增轨道名为 `tracks.boneAttachment`。每条记录包含：

- `frame`、`childBone`：注册帧和道具骨骼名，二者组合唯一。JSON 数组中同帧记录的先后顺序就是注册顺序。
- `parent`：`{"object":"actor","bone":"人物骨骼精确名称"}`。
- `mode`：`keepWorld` 保持注册时姿态，或 `snap` 在注册帧对齐目标骨骼。
- `compensation`：编辑器计算的 16 个列主序矩阵数值，包含注册时的相对位置和旋转。必须是有限、可逆的仿射矩阵。请通过编辑器生成，不应直接填单位矩阵来代替真实注册。
- `offset` / `rotation`：可选的附加位移和角度。在补偿之后、道具自身 VMD 局部变换之前组合；骨骼模式位移使用道具 PMX 单位。
- `unbind:true`：解除该道具骨骼外亲，只需提供 `frame`、`childBone`，不影响其他骨骼。

内部求值先将人物骨骼换算到道具模型坐标。注册时读取道具骨骼的当前全局变换 `G` 和动画局部变换 `L`，目标人物骨骼换算后的变换为 `T`：

```text
保持姿态补偿 C = inverse(T) × G × inverse(L)
对齐挂点补偿 C = inverse(L)
播放时骨骼全局 = T(当前帧) × C × 附加偏移 × L(当前帧)
```

外亲替换所选骨骼的父参考系，其自身 VMD 仍继续参与求值。普通后代继承它的变换；后代若有自己的外亲，则使用自己的父参考系，避免父子重复跟随。原 PMX 文件、网格权重、Morph、刚体和关节均不改写。

编辑已有关键帧时，用不含该旧关键帧及其后续同帧操作的前置状态重新注册，避免重复编辑积累偏移。已保存的补偿直接用于跳帧和回退，不依赖渲染时临时注册。

直接由动态刚体控制的骨骼不允许再被外亲直接控制，编辑器会提示注册失败，应选择其上级动画控制骨骼。穗子等未直接外亲的动态骨骼继续由 Bullet 更新，CPU/GPU 共用同一套父级求值和物理回写。舞台运行时出现缺失骨骼或无效外亲输入会隐藏该绑定期间的道具并输出一次原因，后续有效绑定可恢复。

保存时含骨骼关键帧的文件使用 `version:2`，只含旧轨道的文件保持 `version:1`；两种格式均可读取。旧整模型挂载作为道具外层参考系继续存在，骨骼外亲会转换坐标抵消这层跟随，避免重复挂手。

物理保留的是现有独立道具世界中的刚体、关节、跟骨驱动及挂载惯性。人物与道具的跨模型碰撞体代理不包含在本轮实现中。

## 停止与多人

舞台道具使用会话专属的模型实例与缓存身份，与普通简单挂载的实例分开。停止、重播、切换人物或断线后释放舞台道具动作和模型请求；尚未完成的加载也会取消。舞台中的 VMD、外亲与物理参考系不会写入普通道具实例；不会改写保存的材质显隐、绑定骨骼或握持变换。

从舞台切换到普通自定义 VMD 时，会退出舞台帧驱动、恢复人物第 0 动画层的正常播放速度，释放所属舞台道具会话。旧舞台不再定位新动作，普通物品绑定继续使用其原有路径。

舞台协议继续同步所选道具 PMX/VMD 文件名。观看端从本地对应角色目录解析同名 VMD 和时间轴，因此各端需要放置相同文件。JSON 文件内容和模型设置不会通过网络传输。

## 验证场景

自动测试覆盖解析、关键帧边界、小数帧、直接跳转、回退、循环、延迟加载、独立表演者、模型替换、短 VMD 后继续控制、停止恢复、缺失骨骼处理、渲染/物理矩阵一致，以及隐藏时每渲染帧只求值一次。编辑器测试还覆盖增改删、保存回读、外部文件冲突、预览动画句柄释放、首末帧映射和设置入口可达性。

`python tools/timeline-editor-probe/run.py` 使用生产 `PropTimelineScreen`、编辑器状态、JSON 读写和骨骼选择页，在轻量 Minecraft UI 替身中运行交互探针，并输出 854×480、320×240 布局 PNG。该探针验证界面事件与布局，原生 3D 预览采用明确标识的替身，不作为真实 Minecraft/GL 验收。

`python tools/prop-bone-probe/run.py` 使用生产 Java 外亲逻辑和实际 Release JNI DLL，在 `build/prop-bone-probe/` 生成包含网格、父子控制骨、动态骨和关节的合成 PMX/VMD。分别验证 CPU 与 GPU 骨骼求值路径的同帧多骨注册不跳变、VMD 位移旋转保留、无效输入原子拒绝、动态骨运动及解绑恢复。该探针不运行 OpenGL。

实际游戏需使用目标折扇 PMX、角色和扇子 VMD 核验文档中的 0、3098、3099、3167、3168、3370、3375 帧及相邻帧，并检查延时出现、CPU/GPU、阴影和穗子物理。合成资产与本地其他团扇不能代替原作者动作的视觉验收。
