## 3. 阶段 0：冻结契约与建立基线

本阶段先由主代理产出 `doc/security/HARDENING_CONTRACTS.md` 和 `doc/security/HARDENING_VALIDATION.md`，再分配实现工作。记录基线提交、已有差异、工具链、测试结果、正常资产清单和无法验证的平台；不运行未获授权的发布、推送或资源覆盖操作。

契约包括以下内容，具体实现和共享文件由主代理统一协调：

1. JNI 方法迁移表：旧/新符号、Java/Rust 签名、全部调用方、计数单位、缓冲偏移/字节序、错误语义和 ABI 握手。
2. 配额表：入口、计量单位、单项限制、单文件累计限制、并发/会话限制、失败动作、配置位置、正常与临界测试样本。覆盖分配量、解析/IK 工作量、解码峰值、网络双向包长和响应放大、缓存、下载与解压。
3. 网络操作码表：方向、连接身份、权限、载荷预算、频控位置、响应成本和混合版本策略。
4. 路径与生命周期表：允许根目录、合法相对路径、符号链接、配置键冲突、缓存句柄和原生缓冲的所有权。

原稿中的 64MB、8192、256MB、128 层、256 次、16 个文件、50MB、150MB、65536 字符只是候选值，不直接视为已批准默认值。依据已有正常资产和平台预算确定并记录保守默认值、字节单位、并发峰值及超限行为；不得填入无依据的资产数据，或自行遍历用户未指定的整块磁盘寻找样本。

威胁模型区分远端联机输入、本地不可信资产、可信内置资源和同机进程。源流/磁盘哈希一致性不等同于发布者认证；POSIX 权限也不能宣称防御所有同用户进程替换。关键兼容取舍无法由已有代码和上下文确定时，先使用可用提问工具确认。既定计划范围外的重大架构方案先补计划并取得批准；已批准范围内的常规工作不反复请求许可。

完成条件：基线与共享接口可复核；实现者能据契约判断接受、拒绝、清理和兼容行为，不依赖各自猜测。

## 4. 阶段 1：现有 JNI 边界修复与行为保持拆分

范围为 `rust_engine/src/jni_bridge/`。先修现有源长度、负数、容量和对齐问题，再按职责拆分；暴露地址的方法替换放在阶段 4。全部 JNI 导出模块均纳入清单，复用已有正确的异常边界，不重复包装。

所有批量入口验证句柄有效性和类型、DirectByteBuffer 非空且可写、计数与偏移非负、源元素范围以及目标容量，元素到字节换算使用 checked 运算。明确缓冲起点、独立偏移、Java position/limit 和字节序；不能用目标容量代替源长度校验，也不能只在 Java 检查。验证完成前不写目标；错误不静默截断、不返回看似成功的零值。

复制期间固定源范围并持有对应 Arc 和必要锁，禁止锁外保存 Vec 指针。浮点、矩阵、颜色等目标避免从非对齐地址构造有对齐前提的 Rust 引用/切片，使用经过长度校验的字节复制或非对齐写入。测试负数、零、边界、超源长、短目标、非 Direct、只读和非对齐 slice，以及失效句柄、重复删除、删除与复制并发。

按方法契约捕获可展开 panic 并转换为 Java 可见错误；错误路径自身不得再次 panic，也不吞已有 JNI 异常。捕获边界不能代替指针安全、资源预算或底层 C++ 失败处理。禁止对所有锁机械使用 `unwrap_or_else(|e| e.into_inner())`：区分全局注册表与模型可变状态，只有证明不变量仍成立才恢复访问；可能部分更新的模型应标记故障、拒绝继续求值并受控释放，不连带使无关模型失效。加入可控 panic 注入，验证传播、隔离和资源清理。

按模型生命周期/渲染数据、材质/纹理、动画/相机、骨骼/Morph、共享校验拆分，沿用现有注册表及独立模块，包括 model_handle、animation_handle、evaluation_profile、issue_diagnostics、material_sphere、render_view、tacz_arm_target、tail_options。模块名以实际职责为准，避免新大杂烩。拆分阶段 JNI 符号和有效输入行为不变，检查导出符号，不假设 Rust 重导出就能保证 JNI 可调用。

完成条件：修改文件少于 1000 行；边界、异常、并发生命周期测试通过；拆分前后合法输入数据一致。此时不宣称裸地址接口迁移完成。

## 5. 阶段 2：原生解析、路径、拓扑和依赖

范围为 FBX/VMD 加载器、贴图和模型加载器、`deps/mmd-rs/src/pmx/reader/`、`skeleton/bone_set.rs`、`skeleton/ik_solver.rs`。先核对实际位置与调用链。

FBX 对字符串、二进制块、压缩输入、数组输出及全文件累计分配设置预算。分配前检查乘法/加法、宽整数窄化、文件剩余范围；节点数量、属性数量、层级深度、父边界、end_offset、属性段偏移均验证，循环必须前进，拒绝倒退或越界。`Read::take` 仅为辅助边界；明确截断、输出长度不匹配和不支持编码的错误语义。

PMX 覆盖嵌套条目、字符串和累计分配，先拒绝负数、溢出，再结合最小条目尺寸及剩余数据核对计数。VMD 区分合法缺省的可选尾段和已声明但中途截断的段；损坏段返回错误，不能统一 `break` 当成功。所有读取循环在错误时终止且工作量有界。

贴图按当前 image 版本与 codec 能力配置尺寸/分配限制，并核对解码、转换和翻转路径是否受限。预算包含缓冲副本与并发加载，尽量原地翻转，保留原方向、色彩和球面图语义。

路径按组件检查，拒绝绝对路径、盘符、UNC、设备前缀及逃逸父目录，保留合法相对子目录和既有查找顺序。明确现存父目录与符号链接策略，不能以字符串前缀或仅 normalize 证明隔离。Java 最终文件打开入口同样受控；合法名称中包含两个点不自动等同于父目录组件。

骨骼先校验索引和父子关系，以有界环检测/拓扑构造避免先递归后检查。默认对无法安全求值的畸形拓扑返回加载错误，不自动切环后静默显示；若真实资产依赖恢复行为，先明确兼容策略。合法深层级优先迭代遍历，不能命中递归保护后返回半成品矩阵。IK 同时考虑迭代数、链长、链数及每帧工作量，限额命中可诊断，不无依据修改正常姿态。

依赖清理独立验收：确认 wgpu 0.17 无实际使用后，同步修改依赖、vr_demo feature 和 lockfile，保留 Demo 能力；检查 egui-wgpu 传递依赖，记录实际重复版本变化。不顺带升级整套图形依赖；Demo 若基线已失败，记录既有问题，不伪称本次全部修好。

完成条件：超限、截断、溢出、环和偏移样本有界失败且无残留资源；正常资产有基线对照；受影响 viewer/vr_demo feature 验证完成。

## 6. 阶段 3A：网络、权限、缓存与共享路径

范围为 Fabric/NeoForge 网络适配、common 的 StagePacketCodec、舞台会话/权限/播放/同步、AnimationLibrary、MorphSyncHelper、PathConstants。共享规则放 common，加载器保留线程和连接适配。

readUtf/writeUtf 双向使用相同契约，按当前 Minecraft/加载器源码或官方资料核实 C2S/S2C 整包上限。区分字符、UTF-8 字节、Base64 膨胀和外层头部，在编码前、解码前、对象解析后分别控制体积和集合。不能只放宽 STAGE_MULTI 读取为 65536 字符；若正常内容无法容纳，先调整内容预算，需要分片或新格式则补协议方案和混合版本策略后再实施。

BONE_SYNC 先确认生产接收者及保留用途；确实未使用时停止服务端广播，解码仍检查长度与剩余字节。未知操作码、错误方向和伪造身份拒绝，身份来自已认证连接，不信任载荷 UUID。

频控覆盖 MODEL_SELECT、REQUEST_ALL_MODELS、STAGE_MULTI、女仆与普通广播全部分支；设置请求次数、输入字节和响应数量/成本预算，处理全量请求冷却、状态合并和玩家数量放大。核对 NeoForge enqueueWork 与 Fabric 回调线程，在合法入口以线程安全方式控制排队，世界状态仍在正确线程访问；不能仅在主线程完成昂贵工作后才限流。断线/重连、异常清理和全局状态容量有明确策略，诊断限次。

女仆请求先核实实体类型，再通过既有软兼容入口取得可信 Owner UUID，校验发送者、维度、实体存在性和既有追踪/交互规则。不能将任意可驯服实体当作女仆；依赖缺失、反射失败或 Owner 未知时拒绝并限次记录。

邀请响应只允许既有会话中的 INVITED 成员转为 ACCEPTED，不创建未邀请成员；校验会话、连接身份、邀请有效性、结束/离开后旧包和重复响应。motionFiles 在服务端入口及客户端消费前限制数量、单项长度、总长度和格式；重复项按现有语义处理，默认不静默截断编排。

模型/动作/表情标识复用共享路径契约，保留 FBX 动作名等合法寻址方式，不把结构化标识一律当文件名清洗。动画缓存分成功句柄、失败记录和警告记录：失败使用有界短 TTL 缓存及重复尝试限制，目录刷新时失效；成功缓存说明播放引用、淘汰与唯一释放责任，不使用普通 LRU 直接删除在用句柄。生命周期无法安全淘汰时先限制新增并明确报错，不能冒险回收。

## 7. 阶段 3B：资源引导、加载器与音频

共享路径/错误契约冻结后可与 3A 并行；加载器 ABI 部分须与阶段 4 同批集成。

### 7.1 资源下载与解压

修正并复用已有配额。下载实际读取字节有限额，不能只信 Content-Length。解压统计单文件、总字节、全部条目（含目录）及路径长度；超限立即终止归档，避免为了 closeEntry 再处理无限剩余数据，异常类型与上层捕获一致。

每次使用独立暂存目录，完成下载、可用的可信预期哈希校验、路径校验和解压后再提交。按路径组件判断包含关系，处理不存在目标、现存父目录及符号链接，不跟随链接越界写入。失败只清理本次拥有的暂存内容。

定义完成标记/清单和可重试状态，目录存在不代表完整。已有 3d-skin 可能含用户文件，不能整目录替换/清空；明确缺失补齐、冲突保留、部分提交和失败恢复。测试中断、错误哈希、超限、提交失败及下次启动重试。

若发布流程提供可信固定摘要，按资源版本保存并强制核对；没有时如实保留缺口，不编造哈希。环境变量/系统属性摘要属于可选增强，默认未设置不能宣称发布内容已认证。

### 7.2 文件名和动态库

配置键清洗/编码与网络资源标识拒绝策略分开，避免清洗后同名覆盖。覆盖 Windows 非法字符、控制符、尾随点/空格、大小写不敏感设备名及带扩展名设备名，保留合法中文与 Unicode。

POSIX 提取目录仅当前用户可访问，库文件按加载所需最小权限设置，不机械全部 0700；其他平台走明确分支，保留 Windows/Linux/macOS/Android 逻辑。源流与磁盘摘要在 System.load 前比对，目标独占创建、防现存链接重定向，使用受控临时文件提交并处理多实例竞争。不得宣称摘要比对消除全部检查后替换风险；清理不影响其他进程或已载入库。

版本/ABI 获取异常和不匹配必须向上层传播并终止初始化，不能被现有 catch(Error) 吞掉；已 System.load 的库不假定可卸载后同 JVM 安全重试。

### 7.3 音频

MP3、OGG、WAV 全部限制实际输入、输出 PCM、声道/采样参数及累计解码工作量。大小换算检查溢出，压缩文件体积不代表时长或输出上界。OGG 改为可逐块受限解码，在追加/分配前检查预算，不能完整解码后才拒绝；MP3/WAV 同样在循环内限制，无进展或损坏流终止。

减少堆缓冲、toByteArray 和堆外副本同时驻留，预分配不目信文件声明。解码器、输入/结果/PCM 缓冲与 OpenAL 对象有唯一所有权，在异常、取消、切换和结束时释放一次。每种格式验证正常、空/短/损坏、超输出压缩样本、边界输出和重复切换，记录堆内/堆外峰值和资源回到基线。

## 8. 阶段 4：受管 JNI 与 ABI 同步迁移

阶段 1 稳定后进行。新增接口在有效对象锁保护期内复制，Java 不保存内部 Vec 地址。迁移实际存在的 ReadByte、GetPoss、GetNormals、GetUVs、GetIndices、GetFirstPersonIndices、GetTextureData、材质地址和 CopyDataToByteBuffer；符号以实际声明为准，不照抄报告的近似名称。

Java 覆盖 NativeFunc、各 Port/NativeRuntimeBridge、CPU/GPU 工厂/实例/renderer、纹理加载/仓库、测试替身、示例及 FullModelPreview 等工具。全项目搜索旧符号声明、调用和脚本引用，剩余命中逐项说明；有效调用者未迁移时不删除。

保留早期可调用的版本入口，增加独立 ABI 标识或同步升级双方版本；新 Java 在数据方法前握手，旧库/缺失握手明确失败。Java、Rust、加载器、工具与打包库同批交付，说明新旧两端的支持矩阵，禁止为兼容重新开放任意地址读取。

真实 JVM 加载本次动态库并实际调用新方法，错误/旧 ABI 库初始化必须拒绝。核对符号和签名，使用适用的 -Xcheck:jni 检查；分开编译 Rust/Java 不算互操作验证。CPU/GPU 同模型同帧对比位置、法线、UV、索引、材质、相机和骨骼数据；记录复制/分配次数、P50/P95 帧时间，避免每帧重复分配或额外双重复制。

完成条件：生产与工具不再通过内部裸地址取数，新 ABI 在最终打包库可调用，边界、并发、数据和性能回归通过。游戏画面另行验收。

## 9. 阶段 5：集成验证与交付

每阶段先运行受影响测试再集成。用小预算注入验证越界/超限，不以逼近 OOM 的巨大样本证明防护。记录实际命令、退出码和日志，未运行不写通过。Windows 使用当前项目 Gradle wrapper 8.11.1 与配置的 JDK 21；执行前核对实际环境，保留缓存和 daemon。

```powershell
cargo test --manifest-path rust_engine/Cargo.toml
cargo test --manifest-path rust_engine/deps/mmd-rs/Cargo.toml
cargo check --manifest-path rust_engine/Cargo.toml --features viewer --bin viewer
cargo check --manifest-path rust_engine/Cargo.toml --features vr_demo --bin vr-pmx-demo
./gradlew.bat :common:test :fabric:compileJava :neoforge:compileJava
./gradlew.bat :fabric:remapJar :neoforge:shadowJar
git diff --check
```

命令按受影响范围执行；删除 wgpu 时 vr_demo 检查必做。依赖 crate 的测试先核对其实际 feature 配置。最终 Jar 必须使用本次源码对应原生库；需要 `-PnativeResourcesPath=<独立暂存目录>` 时遵循既有构建契约，不能用旧 ABI 或来源不明产物充数，也不改写 tracked natives。核对原生布局、Android libc++、refmap、common 类与 JLayer relocation 等现有打包要求。

| 验收面 | 必要证据 | 证据边界 |
| --- | --- | --- |
| JNI | JVM 实际调用、错 ABI、缓冲边界、并发删除/释放 | 单独编译不证明跨语言可用 |
| 解析/拓扑 | 单项/累计超限、截断、溢出、环、深链及正常样本 | 合成样例不证明所有资产兼容 |
| 网络/权限 | 两加载器编解码、双客户端越权/重放、放大和队列压力 | common 单测不证明加载器线程行为 |
| 文件/资源 | 逃逸/链接边界、下载/解压限额、清理重试与配置冲突 | normalize 不等于文件系统隔离 |
| 音频/缓存 | 各格式输出预算、重复失败/切换、资源回收和在用句柄 | 输入限额不代表解码峰值 |
| 游戏 | 固定模型/动作/镜头/配置下 CPU/GPU、纹理球面图、第一人称、舞台/女仆、适用 Iris 场景 | 探针、构建、shader 编译不替代画面 |
| 发布平台 | 现有 CI 目标、原生 ABI 与最终 Jar | Windows 构建不代表其他平台通过 |

多平台沿用现有 CI 矩阵，关注非对齐/JNI 变更相关 ARM64、Android 和 macOS。缺设备或 CI 证据记待验证，不假称全部平台通过。验证记录逐项标记通过、失败、未运行或受阻，注明兼容变化、配额依据和剩余风险。源码测试通过但游戏未验收时可以交接待验收构建，不能标记整体完成。
