# 模型问题日志使用指南

这份指南用于反馈背部凹陷、袖子或头发像被钉住、碰撞模式抽搐、纸娃娃描边黑块，以及渲染掉帧。只需要操作游戏设置、截图或录屏、发送日志，不需要修改模型，也不需要安装改模软件。

## 打开日志

先使用包含这些诊断开关的新构建进入世界，换上有问题的模型。按住左 Alt，鼠标移到“模组设置”，松开 Alt 打开设置；如果改过按键，在游戏“控制”中查找“配置轮盘”。进入“调试设置”分类，按问题选择下面的开关，然后点击保存并返回游戏。

| 调试开关 | 对应现象 | 日志标记 |
| --- | --- | --- |
| 模型变形日志 | 背部或裙料局部凹陷、变形 | `[DEFORMATION]` |
| 两侧部件物理日志 | 长袖、头发或配件像被钉住、不正常下垂 | `[SIDE_PHYSICS]` |
| 碰撞模式日志 | 严格、稳定、宽松模式表现反常或抽搐 | `[COLLISION]` |
| 描边与纸娃娃日志 | 纸娃娃薄片黑块、轮廓异常 | `[OUTLINE]` |
| GPU 日志 | 半透明部件多或动作时掉帧、GPU 耗时与回读排查 | `[MMD性能]`、`[MMD透明性能]` |

这些开关默认关闭，可以单独开启，不必开启原来的“物理调试日志”或“调试 HUD”。前三项按正在更新的模型约每两秒记录一次；第四项按模型及渲染场景约每两秒记录一次。保存设置可能刷新模型，让刚体重新落定，先等十秒左右，再记录表现。模型实际显示在画面里时才容易取得完整日志；测试时使用第三人称，不要一直停留在设置页面。

“GPU 日志”保存后生效，默认每五秒汇总 GPU 查询耗时、缓冲回读、透明排序及绘制次数。它独立于其它日志和 HUD，关闭再开启时会清空旧采样窗口。请保持模型、相机、光影和配置一致，分别记录站立、走路和跑步；详细采样与汇总方法见 [`tools/translucent-performance/README.md`](../../tools/translucent-performance/README.md)。

2026-10-11 起，前三项常态输出摘要，继续保留接触、最差锚点、速度峰值和未知的新记录类型。候选骨骼、逐刚体等完整明细在首次及每 30 秒输出；`omitted_detail_records` 表示本轮省略的明细数。关闭再打开相应诊断开关可以请求下一次完整快照，开发调用 `ModelIssueDiagnostics.requestSnapshot()` 有同样效果；需要旧频率时，在启动器 JVM 参数加入 `-Dmmdskin.diagnostics.full=true`。该调整减少输出量，未改变原生每两秒采样，也不证明帧耗时下降。

碰撞记录中的 `world_anchor_separation` 是两端世界锚点距离，`linear_limit_violation` 才是线性限制超出量；弹性关节允许一定锚点分离，二者不能互换。接触冲量为当前流形中最大的单个接触点冲量；速度为读快照时的瞬时值，另有全体已扫描动态刚体峰值与截断标记。它们均不是连续窗口的峰值。

## 背部或裙料凹陷

开启“模型变形日志”和“碰撞模式日志”，保持当前碰撞模式，站立十五秒，录下背部与侧面的表现。随后在“物理引擎设置（Bullet3）”中关闭“启用物理模拟”，保存、等待模型刷新，再站立十五秒，用同一视角截图或录屏。

反馈时说明：关闭物理后，凹陷仍在、消失了，还是只是变浅。最后恢复原来的物理开关。无需调整顶点、权重或刚体；这些由开发者根据日志继续排查。

## 袖子 头发或配件像被钉住

开启“两侧部件物理日志”和“碰撞模式日志”，录制约三十秒：先静止十秒，再转身、走几步并停下。把异常部位保持在画面中，说明是哪条袖子、哪束头发或哪个配件；可以在截图上画箭头。

再到物理设置中只关闭“启用刚体碰撞”，保持物理模拟开启，保存、等模型刷新后重复上述动作。说明关闭碰撞后部件是否恢复摆动。关闭碰撞的画面可能出现穿模，这轮只用于对照；测试完恢复原开关。不要同时调整重力、速度限制和其他参数，否则难以判断是哪项带来的差异。

## 三种碰撞模式抽搐

开启“碰撞模式日志”；涉及裙料变形时同时开启“模型变形日志”，涉及袖子或头发时同时开启“两侧部件物理日志”。保持物理模拟和刚体碰撞开启。

在“碰撞稳定模式（实验性）”中依次选择“严格”“稳定”“宽松”。每次都保存设置，等十秒，再录制相同的十五至二十秒动作，例如站立、转身、步行、停下。三轮使用同一模型、同一动作和同一套其他设置。把每轮开始的时间和模式名称记下来，或在录像中展示设置选项。

反馈可以直接写：“严格正常；稳定后裙抖；宽松头发也抖”。不必判断是哪一对刚体，也不必改碰撞组。日志会记录原生引擎实际采用的模式、禁碰统计、接触和关节状态。

## 纸娃娃描边黑块

开启“描边与纸娃娃日志”，让角落纸娃娃显示同一个问题模型。在“3渲2”设置中保持“启用 3渲2”开启，先开启“启用描边”，回游戏等几秒并截图；再只关闭“启用描边”，重复截图。尽量把世界中的角色和角落纸娃娃一起拍到。

注明黑块盖住了原本有颜色的薄片，还是只出现在本来透明的空隙中。如果新构建已经正常，反馈“未复现”即可。顺带写明是否开启光影、光影包名称以及 GUI 缩放；无需修改材质。第四项记录的是绘制前的状态和拟使用的描边路径，不能仅凭一条日志断言已经成功画出描边。

## 发送哪些文件

测试结束后，把本次开启的日志开关关闭并保存。退出游戏，打开启动器中本次实例的“游戏目录”，进入 `logs` 文件夹，复制 `latest.log`。部分启动器给每个版本单独建目录，应以本次实例的游戏目录为准。

最好在再次启动游戏前保存这份日志，新启动可能让 `latest.log` 变成本次新会话的内容。发送完整文件，而不是只截图其中几行；多个模式可以在同一轮游戏里测试，共用一份日志。

一同发送截图或视频，并填写以下信息，直接复制这段即可：

```text
Minecraft 版本：
加载器及版本（Fabric / NeoForge）：
新构建 Jar 文件名：
问题模型名：
开启的诊断日志：
异常部位和触发动作：
各轮测试时间 / 碰撞模式：
关闭物理或碰撞后的变化：
是否使用 GPU 蒙皮 / 光影包：
附件：latest.log、截图或视频
```

前四项模型问题日志含有 `[MMD诊断]`，GPU 日志使用表中单独的性能标记。看不到日志时，先确认已点击保存、模型在画面内、游戏正在运行且文件属于当前实例。如果日志提示“原生诊断接口缺失”，说明 Java 与原生库不配套，需要使用同一新构建的完整模组包并重启游戏。

日志采用限频抽样并限制详细样例数量，不能保证捕捉每一次短暂抽搐或列出模型全部部件。连续视频和异常部位的截图仍然需要保留；看到日志中的“截断”或 `truncated` 不代表模型损坏。
