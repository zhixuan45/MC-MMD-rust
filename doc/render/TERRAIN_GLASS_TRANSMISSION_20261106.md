# 玻璃透射到 Toon 人物

## 实现边界

保持已有不透明地形快照和正常人物投影。先支持已经验证的 BSL 单颜色阴影协议，拒绝带图像写入、计算/几何阶段或未知颜色输出的重绘。

在第三个不透明地形层完成后，备份原 shadowcolor0，以原地形深度为起点重绘一次透明地形。
保存实体绘制前的透明地形深度和透射色，随后恢复原深度与 shadowcolor0。
正常 Iris 实体及透明地形阶段继续运行，世界阴影仍含人物投影。
不从含人物的最终阴影图推断玻璃遮挡，避免透射效果再次受到 PMX 内部网格影响。

主体和描边同时绑定不透明深度、包含透明地形的深度、透射色。
零柔化沿用 BSL 原始透射解码与过滤；正柔化使用同一最终阴影坐标，对遮挡和透射色一起过滤。
未取得透射快照时继续使用现有不透明地形接收路径。

## 必要验证

- 使用真实 GPU 绘制透明地形夹具，检查正常/异常退出后原深度和颜色逐像素恢复。
- 后续人物投影改变世界深度，不改变独立的地形/玻璃快照。
- 接收面位于玻璃前、玻璃后、不透明地形后时分别得到无遮挡、透射、完全遮挡。
- 无色/彩色玻璃、柔化 0/1.5/4、主体/描边、底板亮度、快照缺失与热重载。
- 实际 Iris 字节码检查挂钩在所有实体绘制之前，原始透明地形调用保留。
- 编译和包内资源检查之后，仍需原游戏玻璃场景目测验收。

## 2026-11-06：默认颜色格式导致透射捕获静默失败

用户本地替换后的 JAR SHA256 为 `fa6a6c5c584aa907a766403514b0414b22ac9fbd0c8a556828c89d0888692188`，
已包含透射实现。21:25 的实际游戏日志只有不透明地形深度捕获成功，没有透射捕获成功或异常记录。

对安装的 Iris 1.8.14-beta.1 字节码检查显示，`PackShadowDirectives.SamplingSettings` 的默认颜色格式为
`InternalTextureFormat.RGBA`；BSL 10.1.8 没有覆盖 `shadowcolor0Format`。本机 NVIDIA 驱动对这种纹理的
`GL_TEXTURE_INTERNAL_FORMAT` 查询确实返回 `GL_RGBA`（6408）。旧实现只接受三个定长颜色格式，因而
直接返回 `false`，并且调用方没有报告这一失败。

修复按实际 RGBA 各通道精度识别 8 位存储，为独立快照分配 `GL_RGBA8`，继续保留原有格式的支持。
重放条件和颜色格式检查的拒绝原因现在会去重写入日志；成功日志包含实际来源格式和快照存储格式。
没有关闭玻璃阴影、人物自阴影隔离或人物向世界投影。

新增 GPU 回归将相同夹具分别用 `GL_RGBA`、`GL_RGBA8`、`GL_RGBA16F`、`GL_RGBA32F` 创建，
验证真实绘制、颜色和深度精确恢复、异常退出、后续人物投影隔离与逐帧失效。

验证记录：

- `build/terrain-glass-unsized-before.log`：旧生产代码在 `requested=6408, reported=6408` 时失败于 `Glass capture`。
- `build/terrain-glass-format-after.log`：四种颜色格式全部通过；五套实际光影的 30 组主程序/描边变体通过，
  包括已有的无色/有色玻璃最终颜色采样。
- `build/terrain-glass-format-build.log`：Fabric/NeoForge Java 编译、`testCompat`、`testRender` 通过；
  237 项测试中 236 项通过、1 项跳过。

用户自行构建替换后，22:06:20 的实际游戏日志已确认格式修复生效：

```text
[MMD terrain shadow] captured terrain transmission before entities: 2048x2048, ready: sourceFormat=6408, storedFormat=32856
```

若不具备重放条件，会出现带具体原因的 `terrain transmission unavailable`，不再静默跳过。
以上探针结果不代替用户原玻璃场景的游戏内目测验收。

## 2026-11-06：透射光强被误当成几何遮挡，关闭 Toon 补光

格式修复生效后，用户仍观察到玻璃透光下明显的普通立体明暗。此前的玻璃回归检查了减光、染色和隔离，
没有验证原有 Toon 阳光补光能否穿过玻璃，因此未覆盖这条路径。

`toonSunDiffuseRamp` 原本将透射阴影 RGB 的最小分量同时作为几何可见度和直射光能量。
`toonSunDiffuseFill` 再使用 `smoothstep(0.8, 1.0, toonSunVisibility)` 判断是否启用补光。
玻璃仅吸收或过滤光谱，也会因此被当成遮住太阳；例如中性玻璃透射色 0.65 解码平方后为 0.4225，
补光权重归零。染色玻璃的最小分量更低，同样触发。

修复将这两个输入分开：

- 用 BSL 已有的不透明深度 PCF 样本累计几何可见度，决定是否允许 Toon 阳光补光；
- 透射 RGB 继续参与原包直射光乘法，透射光能量继续控制表面色阶的直射权重，保留减光和染色；
- 自定义柔化滤波使用相同样本权重累计不透明可见度；零柔化沿用原包 PCF；
- 没有增加阴影纹理采样，也没有改变未启用独立透射接收时的原有路径。

新增回归在同一几何和光照下对照补光 0%/70%，分别检查玻璃后与不透明墙后的掠射法线。

验证记录：

- `build/terrain-glass-toon-before.log`：中性玻璃后，0%/70% 的采样亮度均为 0.375968，
  失败于 `Glass absorption must not disable sunlight Toon fill on a grazing surface`。
- `build/terrain-glass-toon-after.log`：中性玻璃后从 0.375968 变为 0.594951；
  红色玻璃后从 0.363068 变为 0.464714。柔化 0/1.5/4 均通过；
  不透明墙后补光前后保持一致，alpha 保持一致，玻璃前后减光、染色、描边、宿主 PMX 深度隔离检查通过。
- 同次 GPU 探针中，五套实际光影的 30 组主程序/描边变体及原有混合明暗、暗部网格接缝测试通过。
- `build/terrain-glass-toon-build.log`：Fabric/NeoForge Java 编译及兼容性/渲染测试通过。

23:02 的新运行已确认用户替换了包含本节 GLSL 的 JAR（SHA256：
`c59fd36c81839e07102fcf0e0b3f096a805c3ad43050a69735b375ebeb5e52ba`），
玻璃捕获仍成功，但用户反馈观感依旧不符。继续定位如下。

## 2026-11-06：用实际片元阳光覆盖率取代整体天空光门槛

用户明确要求透明方块后的 Toon 补光取决于人物上实际受阳光覆盖的区域。
上一节将玻璃吸收与不透明遮挡分开后，`toonPrepareSunlight` 仍用整个模型的
`ToonLightmap.y` 乘上 `smoothstep(0.75, 0.95, skylight)`。
因此低天空光位置即使片元有有效阳光覆盖，仍会关闭或压低整个人物的补光。
此外，原来的 `smoothstep(0.8, 1.0, visibility)` 会让覆盖率不到 80% 的半影完全失去补光。
此前玻璃回归固定天空光为 15，未覆盖这两个条件。

本次保留日夜与太阳高度权重，将有效地形阴影接收路径的补光权重改为：

```text
ToonShaderFlatness × daylight × elevation × fragmentSunCoverage
```

只有着色器确实读取了本片元的独立地形阴影，才使用此规则；没有采样、越界提前返回、
经典接收路径等情况保留原来的天空光保护。片元阴影采样本身不增加额外纹理读取。
不透明墙后覆盖率为 0，因此继续关闭补光；半影连续按覆盖率混合。
玻璃减光、染色仍作用于原包直射光，环境照明继续沿用光影包。

新增诊断使用真实主着色器，在同一 draw 内输出覆盖率、漫反射补光结果和有效强度。
同一几何的左右两半分别位于墙后和玻璃后，测试天空光 1/4/8/12/15、
无色/红色玻璃、柔化 0/1.5/4，验证全部像素满足上述覆盖率混合关系。
还测试真实半影片元、无采样提前返回、月光及低天空光下的最终 RGB 输出。

验证记录：

- `build/terrain-glass-coverage-before.log` 直接优先加载用户安装的 JAR：
  天空光 1、片元覆盖率 1 时，补光强度为 0，漫反射仍为 0.044950，新增回归失败。
- `build/terrain-glass-coverage-after.log`：相同条件下有效强度为 0.7，漫反射为 0.713485；
  所有测试天空光等级均一致。每种透射色均覆盖 10 个实际半影片元，混合关系最大误差小于 0.0001；
  墙后不补光、月光不补光、未采样不冒充有效覆盖的检查通过。
- 无色玻璃最终采样亮度在天空光 8 时由 0.159422 变为 0.301397，在天空光 12 时
  由 0.274965 变为 0.465741；红色玻璃的最终颜色与染色检查同样通过。
- 同次五套实际光影的 30 组主程序/描边变体及已有回归通过。
- `build/terrain-glass-coverage-build.log`：两平台 Java 编译及 237 项相关测试通过
  （236 项通过、1 项跳过）。

本节修改尚未替换进用户游戏；原玻璃场景的最终观感需要本轮完整打包后的版本验收。
