# 地形阴影下的 Toon 底色与底板亮度

基线：`aa4ae65`。运行实例为 Minecraft 1.21.1 / NeoForge 21.1.252，启用 GPU 蒙皮和 BSL 10.1.8。
运行日志已经确认地形深度来源是 Iris 的 2048×2048 阴影 FBO，本次没有改变阴影捕获源、投影坐标或角色投影流程。

## 复现与机制

`LightingProbe.checkMixedLightSurface` 在一次绘制中放置四组不同法线，每一组都横跨同一条地形阴影边界。
关闭高光、边缘光和新增底板亮度，以排除额外材质效果。

修复前 BSL 10.1.8 的完全遮挡侧，四组法线的最大 RGB 绝对差之和为 `0.312407`。
同一输入的原始阴影可见度差为 `0.000000`，说明差异来自阴影采样后的着色。
原先 `albedo * mix(ShadowColor, 1, band) * illumination` 把太阳朝向色阶也乘到了环境光上。
相同位置的不同法线因此会在全阴影中产生额外颜色差，放大模型的法线接缝。
失败记录：`build/terrain-base-before.log`。

已适配光影的地形阴影路径现在记录 `visibility * directDiffuse`，据此调节表面色阶的影响。
完全遮挡时保留环境光底色；有直射光时继续呈现 Toon 色阶。
不直接用 visibility 作为权重，因为低角度受光面的直射补光尚未增加时，单独淡入暗色阶会先把环境光压暗，产生半影暗圈。
无地形快照、通用照明以及未经识别的光影协议继续使用原有色阶逻辑。

该权重是风格化的直射光权重，不是对每个光影包全部环境光/直射光贡献的物理拆解。
天气和昼夜的照度计算继续由原包完成。

## 底板亮度

Fabric 与 NeoForge 的 Toon 设置新增“底板亮度”，范围 0–100%，默认 0，保存后生效。
配置键为 `toonBaseBrightness`，旧配置缺少该字段时为 0；越界值裁到 0–1，非有限值回到 0。

在光影输出编码之前，底色计算为：

```glsl
max(shadedMaterial, max(albedo, vec3(0)) * ToonBaseBrightness)
```

它为材质底色提供最低可见亮度，不向已足够明亮的像素叠加照度。
主体和跟随光照的描边共用这个值，黑色描边仍保持黑色，alpha 不变。
球面纹理和后续材质效果仍保留各自的处理；底板不是后处理完成后的屏幕亮度下限。
夜间和室内也会受到这个手动底色下限影响。高值会压缩明暗对比，可先用较低数值作对照。
角色写入世界阴影的深度和材质裁切没有改动。

## 验证

在 NVIDIA RTX 5070 Ti Laptop GPU 上运行隐藏 OpenGL 上下文，读取实际 BSL/Complementary 源码，通过生产 source builder 生成主体与描边。

- 五个真实包、三维度、实体/手部共 30 组主体/描边程序通过。
- BSL 的 `SHADOW_BIAS=1` 另有 12 组通过。
- 五个包的完全遮挡侧法线颜色差均为 `0.000000`；受光侧仍有可测量的 Toon 色阶差。
  BSL 10.1.8 的受光侧差为 `1.003951`。
- 同次绘制中的四组法线，在柔化 0/1.5/4 与底板 0/15/35% 的组合下，跨阴影边界的亮度保持单调，并保留阴影对比和覆盖率。
- 底板 0/15/35/60% 验证了主体/描边同步、不同包颜色编码、亮部不额外提亮、黑色描边、alpha、通用照明回退和归零恢复。
- 既有地形快照隔离、后续投影深度写入、相机旋转、柔化宽度、着色器颜色隔离与缺少快照时的回退检查通过。
- common Java 测试共 390 项：389 通过，1 项因外部资产缺失跳过。
- Fabric/NeoForge 编译、Fabric remapJar 与 NeoForge shadowJar 通过；复用已暂存 native DLL，未修改原生引擎。

对应日志为 `build/terrain-base-after.log`、`build/terrain-base-normal-bias.log` 和 `build/terrain-base-build.log`。
另修正了两处既有探针问题：Windows CRLF 导致深度 pass 字符串断言失败；旧风格探针仍要求满补光抹平柔和色阶，与 `aa4ae65` 保留色阶的行为不符。
