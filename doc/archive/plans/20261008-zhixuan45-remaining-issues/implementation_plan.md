## 四项问题的判断

### 背部局部凹陷

已观察：第一张图箭头指向腰下背部裙料中央的局部收陷，用户反馈调整物理选项不能消除。图中没有足够证据说明人体背部骨架本身凹陷。

候选有两条，需要先分开。若关闭物理、重新加载并求值相同动画帧后仍收陷，应优先检查该片网格的权重、形态键及骨骼变换。当前实际 CPU 蒙皮忽略 SDEF 的 C/R0/R1 参数，退化成 BDEF2；QDEF 按 BDEF4 处理。GPU 输入同样只导出普通骨索引与权重。因此，如果异常顶点使用 SDEF/QDEF，蒙皮简化确实可能造成旋转时局部体积损失；但未取得模型，不能确认该片使用哪类权重。CPU/GPU 一致只能排除后端差异，不能排除双方共有的简化。

若关闭物理后收陷消失，应优先检查后裙刚体、身体代理壳和自动补全的横向关节。初始化会在原资产之外补身体碰撞体与裙摆横向关节，这些步骤并非由 Strict/Stable/Relaxed 直接开关。错误补全、尺寸覆盖不合适或跨链连接可能改变后裙姿态，仍需实际链和接触证据。

最小验证：同一源模型、同一动画帧，比较原始绑定网格、动画开启且物理关闭、物理开启三种结果；固定相机，核对箭头区域的顶点位移。同步导出该区域顶点权重类型、关联骨矩阵、刚体姿态和关节锚点。若只是光照造成视觉凹陷，顶点位置应不变，关闭光影的对照可进一步区分。

### 两侧袖子 头发和配件像被钉住

已观察：截图中长袖、侧发及细长配件存在外张形态；“不受正常重力、钉在原地”来自用户的动态观察。部位处于身体两侧是定位线索，当前代码没有已证实的“左右区域禁止物理”规则。

先区分刚体运动与最终显示。PMX 模式 0 完全跟骨；模式 1 回写完整物理位姿；模式 2 保留本帧层级传播的位置，仅采用物理旋转。模式 2 不会把刚体平移直接显示为骨骼平移，这是语义边界，并非发现此模式就能认定缺陷。若父链姿态正确，旋转仍应带动后续链段；不能把所有模式 2 改成模式 1 来消除钉住感。

另一个候选是接触锁住：自动补全的身体壳可能与袖子、侧发或附件持续接触，使重力被接触和关节抵消。合成壳一侧允许掩码为 0xFFFF，但实际接触仍要求另一侧掩码也允许。袖子、头发和一般配件不会直接获得裙摆兼容逻辑扩展的碰撞位，所以不能把三类部件都归因于该扩展。

若刚体已运动但骨骼或网格未响应，再追踪回写、非物理中间父骨、追加变换和权重绑定。目前父优先回写已存在，没有找到 PMX 骨索引被重排导致错绑的证据。身体几何推离函数虽保留在源码中，却没有生产调用者；不能将“逐帧强制推离把两侧钉住”当作当前根因，也不应直接启用它来修复，因为点位推离可能破坏关节一致性。

最小验证：对每条异常链同时记录刚体模式/质量、Bullet 模拟位姿、渲染位姿、骨骼世界矩阵和异常网格顶点。做碰撞开/关、原始/合成身体壳、静止/小幅摆动对照。刚体不动且有持续接触查碰撞；无接触仍不动查质量、模式和限位；刚体动而骨不动查回写；骨动而网格异常查权重。新增诊断仅针对选中链，避免逐帧全模型日志。

### Strict 正常而 Stable 和 Relaxed 更抖

已观察：文档报告 Strict 表现最好、Stable 较少抽搐、Relaxed 更剧烈。三张截图只能支持形态对照，不能量化动态抽搐。

已确认的实现差异如下。三种模式不直接改变求解器精度、关节弹簧参数或刚体尺寸；它们主要改变额外禁碰计划。直接连接的约束刚体另有 Bullet 约束禁碰，不因 Strict 而取消。

| 模式 | 额外处理的主要范围 |
| --- | --- |
| Strict | 保留原始碰撞资格，不增加稳定拓扑过滤与裙摆兼容扩展 |
| Stable | 同组动态关节图距离不超过 2 的对；部分初始重叠裙片和共跟骨根兄弟对；初始重叠的动态尾巴/头发与裙摆对 |
| Relaxed | 同组动态连通分量内的全部可达对，以及共根初始重叠对；其过滤集合并非简单包含 Stable 的所有专用规则 |

Stable/Relaxed 还接入裙摆与骨盆/大腿的兼容碰撞位，并处理特定祖先身体壳初始深嵌入。这意味着既可能少了链内支撑，也可能多了特定身体接触；要分别验证。

首要联动候选：初始化先补裙摆横向关节，然后把原始与新增关节一起用于碰撞过滤图。若同组裙片原本是独立纵链，新增环向连接可能把它们合成较大连通网络。Relaxed 随之过滤更多跨片碰撞，Stable 的图距离也可能缩短。接触支撑减少或穿越后与身体反复接触，可能解释“过滤更宽反而更抖”。这是由调用链支持的候选，尚未在反馈模型上验证。

配置保存并非只有落盘：Fabric 与 NeoForge 都会 reloadAll，然后 applyPhysicsConfig；Rust 对模式变化请求物理重建。因此三模式对照必须使用相同源文件和初始化姿态，并等待相同的稳定窗口，不能比较刚保存时的不同初始化瞬态。用原生诊断确认实际模式与过滤数量，不把界面标签当作生效证明。

最小验证：固定动作、帧率、身体壳和初始化流程，分别运行三模式；接着只在诊断副本中关闭新增横向关节，或保持关节求解但用原始关节图计算过滤，比较接触对、角速度尖峰、穿透深度和关节锚点误差。再单独关闭裙摆兼容扩展、祖先深嵌入过滤。每次只改一项，避免将禁用关节造成的姿态变化误判为过滤修复。

### 描边和纸娃娃薄片黑块

用户补充认为此项应该已经修复。当前独立 OutlineRenderPass 对正交 GUI 使用实际显示缩放换算宽度，并临时使用 GL_LESS，避免等深度倒置壳覆盖薄片主体。源码与既有验证记录一致，本轮未重跑历史探针，也没有新的游戏画面验收。

该项先做回归：同一薄片模型在世界与纸娃娃中开关描边，对比 CPU/GPU 与常用 GUI 缩放。若主体不再被黑块覆盖，本项关闭。若只在贴图透明孔洞出现填黑，另按透明裁切处理；当前纯色 pass 不采样贴图 alpha，整体材质透明度并不能保留透明孔洞形状。只有此分支复现后才评审裁切方案，保留独立描边边界。

## 实施顺序与条件修复

第一阶段建立可比较基线。记录实际 Jar/DLL、配置、源模型与动作的哈希，沿用现有 audit_pmx_physics、probe_static_physics、probe_model_physics 与网格探针。先用小型受控夹具覆盖同组多裙链、横向关节、非物理中间父骨及 SDEF 旋转。原始反馈模型未取得时可完成这些验证，但不能宣称原案例已修复。

第二阶段优先验证问题 3。给禁碰对补充来源信息，区分原始关节、合成环向边、近邻规则、初始重叠规则、裙摆兼容和祖先身体壳过滤；接触诊断优先复用现有包装层。若证实合成环向边错误扩大过滤范围，将求解约束图与过滤所需的链邻域语义分开，保留环向保形作用与必要的非邻近碰撞。若只命中初始 AABB 误判，则收窄对应规则的几何/部位条件；若新增身体碰撞导致异常，则只修该资格或代理覆盖。不得直接把全局模式改为 Strict，或默认取消所有自碰撞来掩盖问题。

第三阶段按异常链处理问题 2。确认模式、质量、接触和回写分支后，只修实际失效的边界。合成壳误检时改检测与几何覆盖，并保留原模型合法身体碰撞；模式 2 父链传播失效时修传播，不改变模式语义。若资产本身使用了不符合目标效果的模式或权重，另做带备份的候选资产副本，不批量覆盖源模型。

第四阶段处理问题 1。物理导致的凹陷接入前两阶段结果；非物理形变则用异常顶点和可信参考求值比对 SDEF/QDEF、追加变换与形态键。只有命中特殊权重算法时，才扩展完整 CPU/GPU 蒙皮支持，明确 GPU 缓冲/JNI 契约和兼容方式，另行评审该跨层方案。不能只修 CPU，让 GPU 继续输出不同姿态。

最后执行问题 4 与已有物理行为回归。保存修复前后同机同场景画面、日志和样例哈希，分别标注静态审计、自动测试、受控探针及游戏验收的完成状态。

## 验证与验收

过滤修复的测试必须观察实际接触或受力结果，不能只断言新规则返回预期列表。覆盖多链被横向边连接后的非邻近碰撞、原资产显式禁碰、共根附件和衣物与 FollowBone 身体壳接触。骨骼回归覆盖模式 1 完整平移、模式 2 父优先传播、跨非物理中间骨与乱序索引，并复核零子步/卡顿恢复没有显示姿态回退。

相关 Rust 定向验证通过后运行库测试；涉及 Java 时先依 gradle-ide-parity 技能完成 JDK/构建环境对齐，再编译 common、Fabric、NeoForge 并运行实际受影响的测试。构建或隐藏 OpenGL 探针通过仅作为该层证据，不代替游戏验收。

游戏验收使用确切反馈源模型和可比较的动画：背部裙料不再出现异常局部收陷；两侧动态链按其合法模式响应重力、动作和接触，没有持续锁定；三模式从相同初态播放不再出现本次策略引入的持续抽搐，同时保持必要身体阻挡；纸娃娃薄片主体无黑块。不同模式可以有不同姿态，不能要求每个模型的表现天然按模式名称单调改善。

本轮交付的是分析与计划。进入实现前需用户确认本计划；若进一步证实需要骨骼/蒙皮接口重构，先提交对应实施方案再审批。
