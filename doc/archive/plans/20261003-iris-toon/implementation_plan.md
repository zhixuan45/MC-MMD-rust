# Iris 与 Toon 并用修复实施计划

2026-10-03。用户已批准本方案，要求保留 Toon 与光影同时开启；未知契约先提示，由用户手动关闭 Toon。根目录已有的 implementation_plan.md 属于 VMD 平滑工作，保留原文。

## 已核对的原因

测试实例为 `D:\minecraft\.minecraft\versions\1.21.1-NeoForge_21.1.252`，Iris 为 `1.8.14-beta.1+mc1.21.1`。实例中安装的 MMD Jar 与本次工作区打包文件 SHA256 相同，已排除未安装上一轮修复包的情况。远程 issue #1 的评论 https://github.com/zhixuan45/MC-MMD-rust/issues/1#issuecomment-5966130843 提到部分光影干扰三渲二、需回退默认渲染，但没有提供保持两者并用的实现。

实际 `ComplementaryShaders_v4.7.1.zip` 中，`shaders/program/gbuffers_entities.glsl` 第 332 行先以 pow(rgb, 2.2) 转为线性颜色，第 452～460 行定义 DRAWBUFFERS 为 037，启用高级材质和反射时为 03761。输出槽 1 是材质信息，槽 2 是白色标记；高级模式另用槽 3 写编码法线、槽 4 写原始颜色。后期 `composite5.glsl` 将颜色转回显示空间。

当前 Toon 直接输出显示空间颜色，并固定将槽 1 写为法线、槽 2 和槽 3 写为黑色，缺少槽 4。这会抬高显示亮度，并让材质处理读取错误数据。描边采用相同输出布局，也需同步修正。用户的 Toon 开关对照与这条调用链吻合；尚未用 GPU 抓帧量化各错误通道的贡献。

实例中的 `BSL_v8.4.02.2.zip` 也采用线性颜色，但实体输出按选项使用 0、08、0367 或 08367，不能套用 Complementary 的布局。普通实体程序、第一人称手部程序和程序回退关系必须分别核对。

## 方案与范围

保留现有 CPU/GPU 蒙皮、Toon 色阶、高光和描边计算。在它们的输出边界新增小型兼容适配层，将 Toon 结果转换成当前光影程序要求的颜色空间和缓冲内容。Iris 仍负责自己的帧缓冲、光影后处理和阴影通道；沿用上一轮阴影修复。不开启“光影时自动关闭 Toon”。

首批覆盖实例中的 Complementary 4.7.1 与 BSL 8.4.02.2，并验证无光影时的现有行为。其他光影包不宣称通用兼容，也不按相似文件名盲目套用格式。未知布局需明确记录诊断，后续按实际程序增加适配。

已知语义的槽位重排可以映射，未知、重复、缺失必要输出或包含额外实体阶段时判为未适配。绘制前显示一次提示，包含光影名称和具体原因，建议画面异常时手动关闭 Toon；继续保留 Toon 和已有输出，不自动改配置或临时关闭。按包和问题去重，避免每帧提示。兼容程序编译失败也采用相同提示策略。

Iris 兼容层以反射读取当前包、维度和实际程序信息，避免硬编译依赖 Iris。已经通过本机 Jar 验证 `Iris.getCurrentPack()`、`getCurrentDimension()`、`ShaderPack.getProgramSet()`、`ProgramSet.get()`、`ProgramSource.getDirectives().getDrawBuffers()` 存在。实施时先核对当前 ShaderInstance 到实际 ProgramId 的关系及其回退链，再用解析后的输出布局选择兼容策略；不能仅凭包名或 OpenGL 附件编号推断 colortex 语义。只在包、维度或程序改变时刷新缓存。

每个适配策略明确颜色编码、材质默认值、法线编码、标记及可选输出槽。按原光影程序核对中性的非金属材质和光照字段，再实现对应输出；不把全部附加缓冲一律清黑。主着色器和描边共用策略，避免只有模型主体修复而轮廓仍污染缓冲。核对 Iris 对各缓冲的混合设置，防止现有统一 Alpha 混合覆盖材质输出要求。

本次保留 Toon 已计算的前向明暗，将最终颜色在线性空间编码后交给光影后处理，并为延迟材质处理提供中性且符合定义的数据，避免重复实体光照。人物色阶仍由 Toon 控制，场景与整体后处理由光影包控制，人物投影沿用 Iris 阴影通道。这不等于复刻每个光影包的全部实体光照及反射效果。不能使用除以 128 等未经实体程序证明的缩放：实例中的该常数属于 bloom 或噪声计算。

## 文件和调用链

预计修改 `compat/iris/IrisCompat.java` 或新增其相邻的元数据读取类；新增独立的 Toon 输出策略类，负责包及实际程序布局解析、策略缓存。修改 `render/shader/ToonShaderBase.java` 和 `ToonRenderHelper.java` 传递策略，并同步 CPU 的 `OpenGlModelRenderer.java` 与 GPU 的 `GpuSkinningModelRenderer.java`。修改 `assets/mmdskin/shader/toon_main_body.frag.glsl` 与 `toon_outline_body.frag.glsl`，按需要新增简短的输出模板。最后补充相关测试和 index.md。

调用链为：实际 Iris 实体或手部程序 → 已解析输出契约 → Toon 策略 → 两后端绘制 → 对应 G-buffer 输出 → 光影后处理。阴影仍直接使用 Iris 阴影程序。现有配置与模型资源格式不变，不修改用户的光影包源码。

预估约 8～12 个源码、资源和测试文件，数百行以内；每个文件保持低于 1000 行，注释用简短中文。实施时 Luna 子代理负责独立的输出策略和测试，主代理负责 Iris 元数据、两后端整合及验收；禁止子代理创建新对话或继续派生子代理。

## 验收和交付

定向测试覆盖两光影的输出布局、可选材质及灯光选项、实际程序回退、策略切换和显示空间转线性颜色。保留已有阴影矩阵、第一人称姿态和防走光回归，编译 Fabric 与 NeoForge，并打包确认着色器资源实际包含在 Jar 中。

实机验收使用同一模型和场景，对比无光影、BSL、Complementary 下的 Toon 开关；检查主体颜色、色阶、描边、人物投影、第一和第三人称，以及关闭光影后能否正常恢复。切换高级材质/反射选项时也要验证缓冲布局改变。普通实体通过后继续核对背包、纸娃娃和手部相关路径，不以单张截图替代全部验证。

交付 NeoForge 可替换 Jar、定向测试结果和实际画面对照。测试包先在工作区生成；安装到 D 盘实例前确认文件写入权限并备份原包。若无法完成实机交互，只报告已验证的编译和测试部分，明确保留视觉验收项。
