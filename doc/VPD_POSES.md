# 在动作轮盘使用 VPD 姿势

1. 将 `.vpd` 放入游戏目录下的 `3d-skin/CustomAnim/`。也支持角色目录、角色的 `anims` 子目录以及 `DefaultAnim`。
2. 打开“动作选择”轮盘，点击右下角明确显示的“动作轮盘配置”。
3. 点击刷新，将标记为 `[VPD]` 的姿势加入已启用列表并保存。返回轮盘后列表立即更新，无需重新打开游戏。
4. 在动作轮盘选择姿势；选择“恢复默认姿势”解除 VPD 骨骼覆盖。播放普通 VMD/FBX 动作也会先解除遗留的 VPD 骨骼覆盖。

VPD 使用静态骨骼/Morph 姿势应用接口，不会作为 VMD 动画交给动画加载器。同名的 VMD 和 VPD 可以并存并分别启用。原有表情轮盘和 VPD 选择页仍可使用。

动作同步发送目录来源和资源标识，接收端从自己的动作资源目录解析文件，不传输本地绝对路径或文件内容。各端需要准备对应的 VPD；文件缺失或应用失败不会广播为成功。女仆动作轮盘继续只显示其支持的 VMD/FBX 动作。

在非舞台状态，含匹配骨骼的 VPD 会进入静态姿势状态，暂停待机、持物及受伤动画层；物理和蒙皮仍继续更新。移动、恢复姿势或切换普通动作会退出该状态。舞台播放期间只应用覆盖，不拆除舞台动画层或停止播放器。

姿势恢复只解除骨骼覆盖，现有“重置表情”仍用于同时清除表情。VPD 表情权重会跨帧保持，显式修改某个表情权重可解除该项覆盖。

选择后聊天栏会显示文件名和匹配的骨骼、表情数量。文件不存在、读取/解析失败、模型未加载和完全无匹配会分别给出提示；解析错误详情及匹配总数会写入客户端日志。完全无匹配时保留之前已应用的 VPD。

解析支持 UTF-8（含 BOM）、Shift-JIS/CP932，以及同一文件内混用 GBK 中文模型名、自定义骨骼名和日文标准骨骼名的导出。结构和数值按 ASCII 解析，注释不参与名称解码；旧编码存在歧义时优先采用 Shift-JIS 名称，未匹配当前模型时才尝试无损解码的 GBK 名称。无法解码的名称仍会报错，不使用替换字符吞掉错误。

程序回归覆盖实际解析后的 VPD 到 CPU/GPU 骨骼、蒙皮矩阵及连续帧表情的应用，以及姿势状态进出和加载失败反馈。另已用用户提供的混合编码原文件完成 404 个骨骼、0 个表情的解析，并在按正确中日文名称建立的测试骨架上验证全部匹配和连续帧矩阵。这些程序验证不等同于用户 PMX 的游戏内画面验收。

# 扇子穗子的逐帧物理

扇子、挂接骨骼及道具偏移现在组成独立的物理参考坐标系。每次有效物理步进前，动态刚体保留上一帧的世界姿态，再在新参考系中继续求解；重力也转换到当前参考系。因此角色手部的平移或旋转不会只把整条穗子刚性拖走。

VMD 仍与舞台帧同步定位，物理使用独立的正时间步长，短动作停在末帧后也可继续物理演算。显式重播/回退、传送或缩放变化会重同步动态链。主画面、阴影等同帧重复绘制仍只步进一次。

需要开启全局物理和模型设置中的“道具物理”，PMX 中的穗子需要有效动态刚体和关节。道具与角色仍是独立物理世界，本次不引入两者之间的碰撞求解。

新增程序回归覆盖：同名 VPD/VMD 扫描与轮盘标识、姿势失败不广播、绘制与物理变换一致、外部逐帧 VMD 定位下的 CPU/GPU 物理推进、挂接参考系变化后的世界姿态与重力方向，以及传送/缩放重同步。真实扇子 PMX/VMD 的游戏画面仍需实际资源验收。
