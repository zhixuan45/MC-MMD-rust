# 穿模与舞台短暂回弹诊断（2026-10-04）

本文件保留修复前调查快照。后续代码修复与新构建验证见 [修复验证](PHYSICS_CLIPPING_FIX_VALIDATION.md)，Oguri模型交接见 [资产标准](OGURI_PHYSICS_ASSET_STANDARD.md)。下文的“当前代码”均指本次修复之前的源码。

本次任务是先定位原因。已读取项目索引，审计用户提供的两个实际 PMX，并用当前源码重新编译诊断探针。没有修改生产物理代码、游戏配置或模型资产。新增两个独立 examples，原有未提交修改完整保留。

问题严重程度为核心物理功能受损：既有移动时裙腿交叉，也有袖、发、服装和饰件多处同时异常。图5来自远端用户的 Stable 构建，本地当前源码不能自动代表该用户实际加载的 DLL；以下区分代码缺陷、资产事实、离线复现和现场待证据。

## 结论一：PMX 碰撞掩码在运行时被反读

这是目前证据最完整、影响范围最广的穿模原因。`deps/mmd-rs/src/pmx/reader/rigid_body.rs:51` 直接读取原始 u16；`src/model/loader.rs` 原样保存。但 `src/physics/mmd_rigid_body.rs:595` 返回 `!un_collision_group_flag`，`garment_contacts.rs:24,60,62` 又按同一反码语义建立碰撞计划。

字段名包含 un_collision 容易误导：这里的原始位值实际作为 Bullet 的“允许碰撞掩码”使用，PMXEditor 的“不冲突群组”复选框显示的是反面。参考实现的完整链路没有取反：[Babylon PMX 解析器](https://github.com/noname0310/babylon-mmd/blob/main/src/Loader/Parser/pmxReader.ts#L734-L738) 直接读取 collisionMask，[物理构造](https://github.com/noname0310/babylon-mmd/blob/main/src/Runtime/Physics/mmdAmmoPhysics.ts#L736-L744) 直接传入 mask；[Saba PMX 读取](https://github.com/benikabocha/saba/blob/master/src/Saba/Model/MMD/PMXFile.cpp#L567-L575) 和 [Bullet 入场](https://github.com/benikabocha/saba/blob/master/src/Saba/Model/MMD/MMDPhysics.cpp#L142-L148) 独立证实相同语义。

图2选中的蝶律刚体 #141 `スカート_11_7` 与实际文件在尺寸、位置、质量、阻尼上对应。它的组号14对应编辑器第15组，原始掩码为 `0xBFFF`：不与第15组碰撞，其余组可以碰撞。当前程序取反得到 `0x4000`，变成仅与第15组碰撞。于是该避开的裙片自碰撞被打开，该接触的身体却被排除。

蝶律共452刚体、645关节，包含248个裙体、44个长袖体和44个耳饰体。这种错误同时作用于多个部位，能够解释图5涉及多条物理链，而非仅局限裙摆。前面审计工具输出中 `excluded` 的标签及“原始 PMX 禁止腿裙碰撞”的解释不成立；原始数值本身有效，解释必须纠正。

Stable 当前补丁只额外开放识别为裙摆的动态体与骨盆/大腿，袖、脚踝、头发和饰件不在补齐范围。它能局部掩盖反读问题，不能纠正整套碰撞矩阵。Strict 也使用错误的基础掩码，因此切到 Strict 本身无法解决。

为验证机制，独立探针只在内存里中和取反，未保存 PMX，也未改生产 helper。在蝶律 sprint、60 Hz 渲染/物理、倍率1.0下，Strict 组裙腿三角形相交候选均值从1044.511降为350.356；Stable 从936.867降为360.222。每组预热2秒，随后3秒取45个样本。相交没有归零，这证明掩码语义显著影响结果，不构成游戏画面完全修复的验收。

Oguri 需要另外处理。D实例 PMX 有84刚体、57关节；专用裙腿碰撞体 #80/#82 的原始值 `0xFFEF` 排除裙组4，而裙 #71 的 `0xFFDF` 排除身体组5。它们在当前取反代码下反而互相允许。这些数据已经与错误运行语义相互适配。尚未确认这些碰撞体是谁生成的；不能直接只改代码，然后假定此资产自然正确。尾部 blocker 也存在同类原始值与当前运行资格相反的问题。

## 结论二：跳帧恢复漏掉动态骨骼回写，已复现一帧全链回弹

Java `BaseModelInstance.update` 接受最多250毫秒的帧间隔，Rust 默认5个60 Hz子步只可消化约83.3毫秒。`src/model/runtime/physics.rs:217-227` 在更大时间间隔下恢复状态并提前返回，没有执行正常路径的 `apply_physics_transforms`。

此前同帧已经执行动画求值和 `update_node_animation(false)`，上一帧的物理骨骼保护也已清空。提前返回后仍执行动画的物理后阶段与蒙皮矩阵导出，所以该帧显示动画/绑定姿态；下一正常帧又显示 Bullet 姿态。看起来像所有部件一起重置，实际物理世界不必重建。

独立 `probe_physics_gap` 对绑定姿态预热180帧后，输入一次0.1秒步长，再输入正常1/60秒。蝶律406个动态关联骨骼中，371个从物理偏移回到绑定位置；最大显示位移3.925623模型单位。Oguri57个动态关联骨骼中36个同样回到绑定位置。两者求解器关节锚点变化均为0，物理保持启用，下一帧恢复物理偏移。由此区分了“显示姿态回弹”和“刚体真正重置”。

用户补充回弹发生于舞台发起者自己的模型，持续约1–2帧。这与上述缺陷的外观吻合。但代码没有两分钟定时重置，尚未确认为什么现场约两分钟出现一次超过门槛的帧间隔。需要对应构建在回弹同帧的 `PHYSICS_GAP_RECOVER delta_time`、帧间隔及必要时GC事件；目前不能把GC或周期性保存当作已确认原因。

舞台包链接已失效，无法对照原舞台动作。舞台seek只设置动画帧号，不直接重置物理。本地逐帧同步会resolve/acquire模型、续期缓存，所以60秒闲置加60秒待释放不是本地发起者稳定播放时的首要解释。现有日志的120秒重复初始化属于72/45、92/66等其它模型数量，无法关联蝶律或Oguri。舞台播放结束会恢复idle并resetPhysics；只有回弹同时进入结束/outro时才应归入这条路径。

## 其它已确认机制与影响边界

远端角色动画LOD跳帧还有一个独立问题：`WorldRenderPolicy.java:25` 把物理启用和 shouldUpdate 相与；`BaseModelInstance` 每次绘制应用该状态，下一更新帧重新开启物理，Rust false→true会请求初始化。这能造成远端角色反复重摆，但不解释本地发起者在持续舞台中的两分钟周期，也不能仅凭“远端报错”就认定图5观察的是远端实体。

当前PMX JNI加载在注册/返回模型句柄前同步执行 `init_physics`，因此没有证据支持该路径“模型显示后才异步建立Bullet世界”。初始化不等于已经完成动态落定；第一次Java update还会只记录时间。动作转场在物理之后对蒙皮矩阵插值，约0.3秒过渡内显示姿态可与实际碰撞体暂时不一致。这些会影响首帧或切换期间，不能单独解释运行数分钟后的持续穿模。

碰撞体覆盖不足仍是有效的次要因素。蝶律开发配置倍率1.0，Oguri D实例倍率0.8，并非都在默认0.70。Oguri大腿半径0.5625在0.8下约为0.45。在当前错误掩码语义下、同一walk输入和修正后的部位分类中，倍率0.8/1.0/1.5的相交候选均值为656.711/583.289/332.889；0.8、120 Hz物理为644.800。增厚明显影响这个代理几何场景，但所有组仍有交叉，且正确掩码下需重新做覆盖对照。不能把当前数字直接转为视觉穿模比例。

Bullet碰撞形状没有启用CCD。当前未提交包装层已包含运动学子步推进和渲染预测；不能假定远端旧构建拥有这些改动。高速、薄体与较大步长仍可能导致漏碰，但需要在碰撞资格纠正后测实际穿越，不能优先用CCD掩盖掩码错误。

## 验证记录与后续修复顺序

诊断目录为 `.tmp/physics-diagnosis-20261004/`。`audit-dielv.txt`、`audit-oguri.txt`保留实际原始参数；`mask-semantics.json`保留双语义配对；`gap-dielv.txt`、`gap-oguri.txt`保留回弹复现；`rawmask-*.json`与`validated-*.json`保留最严重采样帧，资产与源码摘要见两个hash文件。

原有网格探针存在三个分类缺口：英文Skirt模板绕过本地配件排除；腿骨英文别名不全；名字含skirt_collider的静态人体壳把腿顶点归为裙。独立副本修正这些问题并增加空分类拒绝条件。旧 `dielv-*`、`oguri-*`、`semantic-*` 文件属于探索中间结果，不用于最终结论。最终有效帧使用 `validated-*` 和 `rawmask-*` 前缀。几何检测排除材质整体透明，但未按贴图逐像素alpha剔除，且基于主导骨权重分类；蝶律绑定姿态也有986个相交候选。因此这些数据只能做受控对照，不能替代截图或实时渲染验收。

本次离线编译诊断examples成功。只有既有库的MSVC链接消息及既有审计工具未使用项提示。没有运行Java构建，也没有替换游戏Jar/DLL。新文件分别57行、约300行。

下一阶段应首先统一碰撞掩码的实际允许语义：同时覆盖刚体、garment计划、合成碰撞体、资产审计器和测试夹具，避免只改一个取反函数而把合成壳的0值解释为全禁碰。用图2实际PMX数值与两个参考实现建立回归，替换当前依错误语义编写的自证测试。Oguri专用碰撞体需先确定数据来源与预期，并按原始文件备份/候选验证流程另行处理。

随后修复跳帧分支的回写完整性，保留已有动态姿态并保证恢复帧也能输出物理骨骼；验证100毫秒卡顿前后不再集体回到绑定姿态。远端LOD的“跳过更新”应与物理启用生命周期分开验证。最后在正确碰撞矩阵下评估厚度、时间步、CCD、关节和蒙皮覆盖，而不是先扩大所有刚体或放松所有约束。
