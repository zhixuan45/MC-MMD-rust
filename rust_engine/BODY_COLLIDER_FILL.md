# 身体碰撞刚体自动填充

物理设置提供两个独立开关，Fabric 与 NeoForge 均支持：

| 设置 | 配置文件字段 | 补充范围 |
| --- | --- | --- |
| 自动补充上半身刚体 | `physicsAutoUpperBodyColliders` | 缺失的胸部、颈部支持 |
| 自动补充下半身刚体 | `physicsAutoLowerBodyColliders` | 缺失的骨盆支持 |

两项默认开启；旧配置文件未包含这些字段时也使用开启值。关闭某项只禁止该区域新增身体碰撞体，保留模型原生刚体与关节。保存后已加载模型在下一次物理更新时重建，无需重新进入世界。

实现分为独立阶段：

1. **检测**：`body_collider_synthesis/upper_body.rs`、`lower_body.rs` 分别提供 `detect` 和 `apply` 操作。检测读取原始刚体、绑定骨骼与绑定姿态，返回候选计划，不创建 Bullet 对象。
2. **应用**：`apply_body_collider_fill` 分别检查两个开关，只处理开启区域的候选；在临时 Bullet 世界中检测旋转碰撞形状是否与原生动态刚体初始相交，跳过不安全候选。骨盆探测使用至少完整尺寸的保守包络，并覆盖倍率大于 1 时的放大尺寸：实际构建只会对符合裙摆接触条件的身体刚体缩放，不能假定所有候选都会缩小。因此，即使某候选在缩小后不相交，只要完整尺寸相交也会跳过。此检查不运行模拟，也不修改原生碰撞掩码。
3. **构建**：运行时把获准新增的刚体追加到原生列表后构建模型物理。原生刚体索引和关节引用保持不变。

原生支持识别结合刚体形状与绑定骨骼，排除零体积、过细锚点和配件。胸部、颈部单独检测；上半身模板名与实际下半身骨骼不符时，以识别到的骨骼区域为准。保留 `bust` 上半身别名，绑定自定义或缺失骨骼时仍能通过刚体本地名或通用名识别原生支持。英文部位名按词段匹配，避免将 `membership`、`necklace` 当作 `hip`、`neck`。生成位置从右手骨骼空间转换到 PMX 空间。

取消旧的固定偏移臀部胶囊补造。洛天依「杏辞」与短发希儿「栖于永夜」都有原生下半身支持，旧逻辑却额外放入与后裙相交的胶囊，导致静止凹折。现在只补真正缺失的骨盆支持，不再重复补入该胶囊。

配置通过独立 JNI 方法 `SetBodyColliderFillConfig(upperEnabled, lowerEnabled)` 传入，保留原 `SetPhysicsConfig` 的参数布局。更改任一开关会标记已加载模型重建。调试快照分别记录上、下半身的实际与请求值；填充日志记录检测计划和被初始交叠检查拒绝的候选。

覆盖的回归包括：原生支持绑定不同骨骼、`bust` 别名与缺失骨骼、错误模板名、过细锚点、坐标转换、旋转箱体交叠、长胶囊不相交、完整及放大骨盆与尾巴/配件/裙摆的初始交叠、检测与应用分离、上下半身独立启停、旧配置迁移与持久化。

## 本次验证

- Rust 库测试：196 项通过；单独串行运行的原生资源生命周期测试通过。
- 两项独立集成测试：四种开关组合重建成功，原生刚体保留；尾巴/配件场景的完整骨盆和裙摆场景的放大骨盆在初始相交时被拒绝，不相交时仍能补入。
- Java 测试：128 项通过，包括旧配置默认值与两项开关独立持久化。
- JDK 17、21：生产加载器加载 Linux x64 原生库；两款实模型上的 JNI 开关切换与活动配置快照一致。
- Minecraft 1.21.1 完整 Gradle 构建通过；Fabric、NeoForge 发布包均含与当前 Rust Release 一致的 Linux x64 原生库。
- 实模型：洛天依「杏辞」、短发希儿「栖于永夜」，分别以身体倍率 0.70、0.80 和四种开关组合模拟待机 10 秒。原生刚体数分别保持 470、359，未新增重复臀部碰撞体；选定后裙区域未出现此前的正 Z 向内折陷。

这是引擎数值与 JNI 验证，尚未运行 Minecraft 画面或 Windows 原生库。长发希儿的两套裙链交叉关节与大原生碰撞壳属于其他问题，本改动未修改它们。
